# Batch 27：Android 活会话暂停与恢复

此前 `onPause` 会关闭音频、视频并结束 Activity，随后销毁 VM。本批将后台暂停与明确销毁分开：Home 或临时离开应用时保留同一个会话，返回前台继续；明确退出或 Activity 销毁时才释放 VM 和媒体资源。

本批只保证仍存活的 Activity / 进程内恢复，不是持久存档，也不保证系统杀进程或 Activity 重建后的恢复。继续使用共用 Rust Runtime、SAF 原始 DAT 和 BLESS 原生 ARM64 真机，没有修改脚本解释器、资源格式或游戏脚本。

## 实现

- `ActiveClock` 从有效时间中扣除暂停时长；`SessionTimeline` 保留定时任务的剩余延迟和顺序，暂停期间不派发请求完成通知、帧回调或后续定时动作。已提交的单次 JNI 调用允许收尾，结果留待前台交付。
- wait、wipe、震动、闪光、角色动作使用有效时间或暂停队列。Android 仍持续请求动作帧，由 Rust 决定完成；恢复不重新建立动作队列。淡入淡出动画使用 `ValueAnimator.pause/resume`，关闭仍取消动画。
- 音频暂停后保留 MediaPlayer、位置、指令音量和淡出状态，返回时重新获取焦点。异步准备期间进入后台不会启动音频或提前 ACK；已完成、已替换的播放器不重新启动。
- 视频保留原来的工作线程、Rust 解码器、部分写入的 PCM 和帧计数。Surface 销毁只阻止呈现，不再等同于跳过或播放失败；新 Surface 可用且应用处于前台时继续。AudioTrack 改为非阻塞分段写入，避免暂停时工作线程卡在写入调用中，无法响应销毁。
- 视频的有效超时不包含后台等待；结束时仍排空音频并核对媒体时长。销毁会唤醒等待线程，在原工作线程关闭解码器。JNI 的线程归属不变。
- 未交付的宿主包和位图在销毁时走取消清理，避免后台积压的回调在 VM 销毁后继续推进。

## 专项验证

`platforms/android/verify_lifecycle.py` 使用真实 Home/后台操作和既有 Activity 前台恢复，核对 Activity 实例标识、PID、有效时钟、暂停期间稳定日志、音频状态和资源清理。转场与动作的精确暂停点由显式探针参数触发；普通运行不启用这些注入。

- 61 页五次往返：首个 fade、开场视频、BGM 对白连续两次、角色动作。逐页 JSON/PNG 对照既有桌面参考，恢复后继续到第 61 页。
- 动作测试在显示第一帧非零动作后才进入后台。最终样本暂停前显示 19 ms 帧，恢复后从 71 ms 帧继续，264 ms 有效时间完成；实际墙钟跨越 2983 ms。不是只停在起始姿势，也不是恢复时直接跳到终点。
- BGM 在后台 500 ms 和 1500 ms 分别取只读样本，要求暂停状态和位置完全一致；恢复调用 start 之前的位置也必须一致，恢复后仍使用同一个播放器实例。刚执行 pause 与已经 start 后的瞬时位置不作为精确位置对照，避免混入媒体时间戳更新。
- 视频实际经历 Surface 销毁、重建后继续，解码器只启动一次；分别检查返回剧情和自然结束。
- 独立销毁场景在真实剧情开场视频播放后进入后台，再由探针调用 Activity.finish，核对等待线程退出、视频关闭原因 3、解码器关闭无错、VM 清理以及不进入下一页。没有用 force-stop 冒充析构验证。
- 保留上一批音频焦点、失焦准备 ACK 和重复淡出专项，检查生命周期调度没有破坏它们。

前期未通过的验证轮次不计作验收：修正了测试驱动重复读取追加日志导致的事件配对竞态；将不合适的暂停后/启动后瞬时位置差比较改为后台两次稳定采样和启动前位置比较；修正了回前台后继续复用点击坐标导致的输入未送达；最后将动作暂停点加强到已显示非零动作帧，并保留 wipe/震动原有的首帧 vsync 入口。最终结果必须全部对应同一个 APK。

## 最终验收

最终 APK SHA-256：`c1f10241d8fef4607e5af2a9f9fc6d14e0d9bc2062d2ccdceb8916e00d6634f2`。所有专项和完整回归使用同一 APK，设备为 PGKM10 原生 ARM64、native bridge=0。仅测试 BLESS，未使用模拟器或 root。

- 61 页、5 次会话往返全部通过；视频自然结束独立场景另完成 1 次往返，共 6 次。Activity 实例与 PID 保持一致，暂停期间没有新 ACK 或动作帧派发。
- 视频自然播放到 2497 帧、4590720 个双声道 PCM 帧，播放头追上全部已写入样本；没有重新启动解码器，关闭无错误。实际后台销毁场景确认根 VM 释放为 0、解码器退出且不进入下一页。
- 普通模式的 793 页逐页 JSON/PNG 与上一批一致，493 次音频请求通过资源哈希和播放事件核对；ENV 观察到 10 次回绕，SE 观察到 3 次回绕，停止通道与缓存清理检查保留。
- 11 个动作页面共 87 帧，通过原始 DAT/Pillow 和既定原版曲线的独立重建；wipe、震动、闪光的捕获帧通过已有独立核对。
- 上一批的临时失焦、失焦期间异步准备/ACK、重复淡出专项再次通过。
- Rust workspace（含 Runtime 49 项；既有 ignored 项不计通过）、Clippy 全 targets、fmt、15 项 Python 测试通过。Kotlin 有效时钟与音量测试通过。

`research/lifecycle-batch27-summary.json` 汇总最终报告的哈希；对应 native、destroy、movie、audio、story、frames 和 audio-evidence 七份记录。游戏资源、APK、截图、音频和原始捕获帧均未提交。历史验证报告没有修改。

## 复现与边界

- `platforms/android/verify_lifecycle.py`：61 页五次往返；`--movie-only` 验证暂停恢复后自然播完；`--destroy-paused` 验证后台销毁。
- `platforms/android/verify_audio_state.py`：上一批音频状态专项。
- `platforms/android/verify_story.py`：原有 793 页有界正常回归，继续要求 ENV、SE 实际循环和通道停止检查。
- `research/verify_lifecycle_batch27.py`：独立重放最终报告，检查构建一致、同一实例、背景时间未计入有效时间、无后台 ACK、播放器与动作进度、单次解码器启动及自然结束。
- 历史 `verify_*cancel.py` 和 `verify_story_lifecycle.py` 保留旧批次的销毁式 onPause 断言，并已注明历史用途；它们不代表当前的 Home 行为。没有把旧断言改成无条件通过。

仍待后续处理：系统终止进程后的可恢复存档、Config 音量与文字交互、原版快速点击语义及跨页动作调度。本批没有声称解决这些问题，也没有新增其他平台宿主。
