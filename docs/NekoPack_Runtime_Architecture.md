# Rust + Kotlin 运行时架构提案

本文为设计，不代表代码已经存在。约束来自用户项目要求；格式证据见 [Sources.md](Sources.md) 的 N2、X2、G1/G2、L1，Android 文件访问依据 A1。

## 边界

Kotlin 负责游戏库、SAF 目录授权、持久 URI、生命周期、输入和设置。Rust 负责资源查找、脚本执行状态、场景、音频调度、存档。JNI 传递目录清单/文件描述符、输入事件、配置和明确错误；不传商业引擎对象，不执行 EXE/DLL。

```text
Kotlin 游戏库 / SAF / 生命周期 / 输入
                 | JNI
              core 会话
                 |
       archive -> resource -> script -> vm
                    |                    |
                  image         场景 / 音频事件
                    |              |       |
                 renderer <--------+     audio
                         save / compat
```

## 模块与契约（实施时按证据逐步建立）

- `nekopack-archive`：ReadAt/长度输入，版本探测、索引、资源读取；使用 u64 文件偏移，显式错误。保留目录/文件哈希、包顺序和来源。无 UI 依赖。
- `nekopack-resource`：包集合挂载、来源查询、重名/补丁选择和有限缓存；顺序规则尚未验证前不能隐式拍板。未知哈希仍能枚举。
- `nekopack-image`：PNG 与样本所需 MNG 解析，输出像素、对象/帧元数据、时序事件；保留 tEXt，解码与 GPU 上传分离。
- `nekopack-script`：保留原始源位置的 lexer/AST，编码由实际样本 profile 指定；禁止虚构 opcode。
- `nekopack-vm`：变量、栈、调用/跳转、等待与恢复；每步接收事件，输出场景/音频指令和下一等待条件。
- `nekopack-renderer`：场景对象、文本、合成和转场。先基于目标设备与特性评估 OpenGL ES 或 wgpu，不同时维护多套后端。
- `nekopack-audio`：BGM/语音/SE/env 独立通道与结束事件，输出位置/暂停状态；解码器与设备输出分离。
- `nekopack-save`：版本化自有格式、完整会话快照、资源指纹、原子提交。原版存档导入另设目标。
- `nekopack-compat`：有证据的格式/语义差异 profile，禁止按游戏名硬编码剧情；格式变种与游戏版本分开。
- `nekopack-core`：统一会话生命周期、时钟、诊断、资源与 VM/场景协同。

## 文件读取与内存

SAF URI 不转为猜测路径。Kotlin 枚举授权目录并交付可用描述符；不能 seek 的 provider 需要明确的本地缓存策略。Rust 先读取索引，按需 seek 到资源块头；块内反馈解密可能需从该资源开头恢复状态。不要一次载入整个多 GB DAT。[A1、X2、L1]

## 调度与恢复

拟定统一单调时钟，VM 产出 WaitInput/WaitTimer/WaitAudio/WaitAnimation 等内部等待状态；这是运行器内部设计名，不是原版指令。完成事件必须可追溯到发起对象，后台暂停后不能误续播或重复触发。

存档在明确安全点记录脚本位置、调用栈、变量、等待条件、场景层、动画位置、音频位置、随机状态和全局数据版本。加载校验包指纹，重建 GPU/解码资源；先验收安全点恢复，再考虑任意动画中途恢复。

## 验收

资源层用合成边界测试与真实样本/独立工具差分；VM 用原版行为轨迹；渲染用相同时间点截图与像素差异；音频用事件/播放位置对照；Android ARM64 真机验证导入、前后台、触摸、保存与重启恢复。任何一个层的通过不能替代整游戏兼容验收。
