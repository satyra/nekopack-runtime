# Batch 37：快捷键绑定编辑与配置 v2

本批从设置第五页接通 F3～F12 的绑定选择、清除、取消和持久化。按用户本轮调整，仅使用 emulator-5568 回归：宿主为 x86_64，native bridge 为 `libnb.so`，APK 内为 ARM64 代码，属于 **ARM64 翻译执行，不是真机验证**。

## 交互与状态

Rust 设置状态增加待编辑槽位。点击 F3～F12 后，按原版 `ShortCutsWindow` 使用 `LIST` 背景及十种动作和 DELETE 图层绘制弹出列表；选项按压使用对应高亮图层。弹窗存在时只命中弹窗选项，底层槽位、翻页与其他控件不能被穿透触发。

选择动作仅更新同一 VM 的 `Config.ShortCuts[slot-1]`。原版 DELETE（“使用しない”）返回空字符串，本批对应清除绑定。宿主按钮变为“取消选择”，取消只关闭列表；拖出后抬起不提交选择，窗口失焦取消按压但保留弹窗。F1/F2 不可编辑。

选择后关闭弹窗，按当前数组刷新槽位文字。编辑、存储和原始资源渲染均在共用 Rust 运行时中，Android 负责触摸坐标、显示与持久化字节，不维护独立的绑定表。关闭设置后继续使用原来的标题 VM，进入剧情不重新初始化绑定。

## 保存格式与迁移

运行器格式升级为 22 字节 `NKCF` + 版本 `2` + 原有七个配置字节 + 十个 F3～F12 动作 ID。动作 ID 的固定顺序为：空绑定、AUTO、SKIP、LOG、HIDE、SAVE、LOAD、QSAVE、QLOAD、RESET、QUIT；这是运行器存储编码，不是原引擎事件 ABI。

继续接受上一批的 12 字节 v1 载荷：恢复七个已有配置，不覆盖当前 VM 的快捷键数组；正常新启动时数组来自游戏默认配置。下一次保存写 v2。Android 保留原 SharedPreferences 键，避免因键名变化丢失旧配置。

导入在修改 VM 前验证版本、精确长度、全部七项范围及十个动作 ID。恢复默认同时恢复七项已接通配置和 F3～F12 游戏默认绑定；数组逐项取 `ConfigDefault`，不改变 F1/F2。单元测试覆盖 v1 导入、v2 往返、最后一项为空、未知 ID 拒绝且不修改状态、槽位边界和恢复默认。

## 显示与回归

`platforms/android/verify_shortcut_edit.py` 读取本地原始配置 MNG 和设置脚本，独立用 PNG 合成核对五页画面、弹出列表、编辑后和重启后的第五页，并保存各页实际模拟器截图作视觉检查。第二页沿用已有静态示例区域，不宣称实现了动态示例文字或透明度预览。

验证包括：

- F3～F12 十个槽位逐个打开/取消，十种动作逐个通过实际触摸选择。
- 弹窗屏蔽底层命中；滑动拖出不提交；Home 返回后弹窗状态保留。
- 将 F3 设为 AUTO、F12 清空，关闭并重启后仍一致，原有七项配置不变。
- 从修改后的标题进入 BLESS 前三页剧情，页面元数据和场景 PNG 与既有基线一致；明确关闭后 VM 追踪存活字节为零。
- 恢复测试前绑定，再次启动验证恢复结果；不以重置其他配置来清理测试状态。

模拟器 Android 的 `input` 不支持 `motionevent`，验证改用系统 `swipe` 生成实际按下/移动/抬起。UiAutomator 曾返回空根节点；验证器对无效抓取显式限次重试，成功取得当前界面后才操作，不读取旧 XML 冒充当前控件。

结果与 APK 哈希见 `research/shortcut-edit-batch37-emulator.json`；工作区 Rust、隔离原生安全探针、Clippy、Python 检查和 NDK 构建摘要见同批 `checks` 文件。

## 范围

接通的是**绑定编辑与保存**。不宣称 Android 实体 F 键输入分发已接通，也不意味着 SAVE/LOAD、AUTO/SKIP 等所有目标动作都已实现；存读档运行时及其他演出能力仍按原有主线推进。未读取 CG 或回想的详细图像、场景和对白，未把原始素材或截图提交到仓库。
