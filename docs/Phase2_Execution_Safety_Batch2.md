# 第二批执行安全修复

日期：2026-11-06。与第一批原生安全修复一起提交；审计基线为 `7d4d624c`。原始审计、架构文档和历史验证报告保持原样。

## 根 VM 挂起（F04）

当前宿主没有根 VM continuation 协议，因此在 `SQVM::Suspend` 内识别共享状态的根 VM，先返回脚本错误，不进入 suspended 状态。普通脚本异常路径完成栈清理，随后可继续执行；脚本自行捕获该错误并正常执行到结束也属于完成。子协程的同步 call/wakeup 仍保留。

桥接层额外检查实际 VM 状态：如果出现未支持的根挂起，则返回失败并将该 VM 标为终止，不能把 SQ_OK 直接等同完成。开始执行前清除旧结果，防止错误后复用前一次返回值。测试验证根挂起后的错误文本、空结果、正常重试，以及场景 pending request 和 PC 均不被自动推进。

## 嵌套 map（V01）

每个场景调用帧改用分支结束位置栈。完成 map 时按嵌套层级扫描，只匹配当前层的 `.case` 和 `.end`。内层结束弹出内层边界，外层边界保留；`.call` 的调用帧也保留父级分支上下文。分支语法错误或选择无匹配时，不改变 PC、不清除 pending request。

测试包括内外层同名 case、内层调用返回、跳过未选分支、恢复外层执行、无匹配后重新选择、重复选择标签、缺失外层 end，以及扫描超限后 pending 保持不变。原版其他控制结构语义仍未据此扩展。

## 执行预算（F05 执行部分、V04）

Squirrel 的每次 eval 默认分配 1,000,000 条字节码预算，宿主可用 `SystemVm::set_instruction_budget` 修改。预算存于 SQSharedState，根 VM、子协程、生成器和嵌套调用共用；每次指令分发前扣减。零预算不能执行第一条指令。

耗尽后保持 exhausted 标记，脚本 catch 的第一条指令也不能执行；脚本错误钩子不再调用，桥接层以 exhausted 状态判失败，避免 native call 吞掉错误后假成功。该 SystemVm 随后仅允许销毁，不能通过提高预算或再次 eval 重置。需要恢复时由宿主明确重建 VM、恢复其游戏状态，不自动重放已有副作用。绑定的 Rust Variables 按原有同步生命周期解绑；失败前已经发生的变量写入不回滚。

新增子进程测试覆盖无限循环、捕获循环异常、尾递归、子协程无限循环、反复 wakeup、恶意错误处理器、零预算、终止后再次调用及多次正常有限调用。测试子进程 15 秒超时是兜底失败条件，成功依据是运行器返回预期预算错误，不是测试器强杀。

场景 Machine 的 steps 改为只读访问器，使用 `>=` 判断预算。空行、注释、map 行收集和 case 扫描也计入预算；pending 的重复查询不计数，不会重复执行。max_depth=0 在执行前拒绝根帧。步数现在反映扫描工作，不能直接与旧报告的指令计数比较。

### 尚未解决的边界

这不是完整沙箱：编译耗时、单次原生标准库调用（如正则）、原生堆分配/OOM 和外部取消尚未获得预算控制。输入源装载/拆行也不是字节码执行。审计 F05 的这些部分仍开放；F06 变量公共状态不变量、其他 P1 及 Android ARM64 验证不属于本批修改。不得把本次通过解释为可安全执行任意不可信脚本。
