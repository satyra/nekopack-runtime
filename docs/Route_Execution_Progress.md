# BLESS 剧情路线执行验收

通过原始 BLESS DAT 从新游戏连续执行 `1,2,1,2,1,2`。共 12,355 个对白页、60,323 个脚本步骤；验证四章通关标记、尾声标记和全通关标记全部为 1。执行顺序为 EP01 → 片尾指令 → EP02 → `title:9` 的标题菜单入口。另实跑提前结局分支：前两个选项都选 1，5,663 页后由 `024101D` 返回标题，全通关标记为 0。

`preview-route OUTPUT PAGE_LIMIT CHOICES DAT...` 接受逗号分隔的显式选项编号，选项耗尽即停止。请使用新的输出目录。在 DAT 列表前加 `--render` 可执行画面命令和资源检查，仍只保存 JSON。本次执行用页数上限 20000。它保留逐页 JSON 和边界文件，不生成 PNG。到达标题菜单请求时预览会返回非零；只凭退出状态或标题位置不能证明通关，须检查最终变量与尾声顺序：

```text
python research/verify_bless_route.py OUTPUT --ending full
```

普通预览的 10,000 步限制保持不变；路线诊断使用 1,000,000 步上限。脚本运行时执行显式 `.select` 选择、条件 `.load`／`.call` 和只读 `?变量`；第四章入口的只读变量不会被当作赋值。

路线诊断对已知画面指令及片尾播放保留命令记录，直接推进，不验证对应素材、画面时序或片尾实际播放。原脚本的孤立 `.` 按空操作执行。正式宿主没有放宽这些演出限制。本次没有打开或读取 CG／回想入口或内容，也没有做 Android 端到端通关。逐页文件可能含原版剧情文本，只保留在本地，验收 JSON 仅记录执行证据。
