# Batch 33：原版标点换行与自动行末字间距

本批继续完善共用 Rust 文字渲染。BLESS 第 23、63 页原先会把句号单独换到下一行；第 156、217 页分别涉及感叹号与闭引号的换行边界。修改只涉及排版，不改剧情解释、页面文本、PC、角色或音频调度。

## 已确认的原版规则

BLESS 原生 Glyph 排版函数 `0x4a32f8` 使用四组 CP932 字符表；验证器逐项检查表内容、分类函数调用、分支和行结束处理器 `0x4a3f08` 的指令。

- `、。，．`：允许超过行宽继续放在当前行，即行尾悬挂。
- `（〔［｛〈《「『【‘“`：若前一个字符属于此组，在发生溢出时将前一个字符一起移到下一行。
- `）〕］｝〉》」』】’”ゝゞヽヾ々？！：；♪`：若当前字符属于此组，在发生溢出时连同前一个字符换行。
- `…‥―`：只有当前字符与前一个字符相同时才启用上述单字符回带。

自动换行时，已结束行的剩余正间距按 `gap * index / (count-1)` 的整数结果分配到字形位置。最后一行及显式换行不进行这项分配。回带的是一个字符，不是任意长的标点串。

另有一条必须保留的原版分支：若此前的悬挂标点已经使光标超过行宽，下一个非悬挂字符直接普通换行，不再回带。原版这四组表没有包含小假名，因此本批没有增加通用日文禁则；第 81 页专门验证这一区别。

## 实现

`text_render.rs` 在字形栅格化前一次性确定整页位置，逐字显示复用这些最终位置，避免回带导致已显示文字跳动。姓名继续保持单行裁切。自动换行分配空隙时使用宽整数中间值；窄到无法放置回带组合的输入明确报错。

对白覆盖层元数据增加正文相对坐标 `origins`，用于核对每个 Unicode scalar 的排版位置。行数按排版行计算，不再从字形轮廓顶端估算；裁切标志同时检查右边界和底边界。核心不依赖 Android 字形或布局 API。

Android 视图、字体选择、字号 22、行间隔 8 和 VM 执行链路保持现有实现。没有为 BLESS 写单独的剧情或页面修正分支，生产代码不读取原版 EXE。

- `research/text-wrap-batch33-controls.json`：KeepVoice 0/1 各五页，检查逐字、补全/推进两阶段点击、后台冻结与恢复、语音保留/停止以及显示途中关闭后的 VM 释放。

Rust 新增悬挂、回带、连续省略号/横线、正间距分配、显式换行、小假名和窄宽度错误边界测试。截图比较仍采用独立浮点视口/预乘 Alpha 模型，门槛未放宽。游戏素材、字体及完整脚本文本不进入仓库。

## 限制

原版规则的证据来自本地 BLESS 原生代码静态分析，**不是原版 GDI 动态字形截图一致性证明**。字体仍为手机 Noto CJK，advance、轮廓和抗锯齿不能等同 MS Gothic；行高沿用当前普通 22px 对白实现。

这不是完整日文排版库，不包含递归禁则、ruby、富文本、可变字号或粗体，也未验证其他三部的原生实现是否完全相同。217 页回归不等于全篇通关。下一阶段继续从实际剧情中的文字或交互缺口推进，不为未出现的语法扩大抽象。
