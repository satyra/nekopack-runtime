# Batch 21：`[[[[` 左向临时往返与后续对白

本批修复 BLESS `012501:582` 的 `.img1 [[[[` 边界。实现仍在共用 Rust Runtime，Android 继续通过 SAF 读取原始 DAT；只用 BLESS 与原生 ARM64 真机回归，不增加平台宿主或改写游戏脚本。

## 原版语义

`research/verify_original_left_excursion.py` 校验与此前相同的 BLESS 原 EXE，以及原始 DAT 中的命令位置，输出 `excursion-batch21-original.json`。

- `0x43cefe` 每个符号默认计数为 1；`0x43cff2` 将 `[` 的计数从临时水平累加器减去。四个 `[` 得到 −4；`0x43d04f..0x43d05d` 乘以 50，写入动作结构 `+0x0c`，即临时水平分量 −200。
- 默认 duration 为 250 ms。`0x4386b8..0x4386bb` 把该分量读入局部变量；`0x438794..0x4387c1` 用 `sin(pi * elapsed/duration)` 乘以它，再加基准 X。
- 转整数仍以画布中心为坐标原点，向零截断后才加中心。先转换为绝对坐标再截断会在负相对坐标产生一像素差异。
- `0x437c1d..0x437c29` 结束时只提交永久 dx/dy，不提交临时分量。因此 `[[[[` 是一次向左再回位，不是永久左移，也不是四次连续摇晃。

真实场景锚点为 `[1120,360]`，理论中点为 `[920,360]`，结束回到 `[1120,360]`。这些结论来自原版静态代码及脚本，不等于动态原版屏幕或时间轴完全一致。

## 共用实现与边界

`scene::plan` 接受末尾重复的 `[`，按符号数量生成负幅度；纯动作保持原图层顺序、资源和滤镜。数字计数、速度参数、混合符号、绝对位置组合及同一角色的多项动作队列仍不支持。

`Motion::horizontal_excursion` 检查绝对和相对峰值是否溢出，在 Rust 内完成插值。稳定锚点不变，帧请求只使用临时显示位置。继续复用 Page motion、`page_frame` 和 JNI operation 8，Android 不新增运动算法。

新增核心测试覆盖中心坐标截断、开始/峰值/结束、超时回位、整数边界、实际帧像素、提前翻页不提交峰值、旧页请求拒绝及缓存页面不推进 PC。上一批 BGM/语音回执测试也加入 `[[[[`，确认动作不会在音频请求间丢失。workspace 测试通过，Runtime 共 40 项；Clippy、格式检查和 14 项 Python 测试通过，原有显式忽略项不计作本批通过。

## 推进范围

桌面原始 DAT 执行到 500 页，前 269 页 JSON/PNG 要求与 Batch 20 逐字节相同。第 270 页为 `012501:585`，语音 `VE_012501_0011`，角色 1 执行 −200 像素的左向往返；随后页面没有残留动作。后续进入 `012601`、`012602`、`012603`。

新的准确边界是 `012603:211`、深度 2、步数 2650：`.img2 _ >>>>`。它包含两个动作参数，其队列/组合语义需要单独确认。本批保留明确错误，不跳过，也不把两个参数擅自合并为同时运动。

## 验证方法与范围

- `verify_excursion_batch21.py` 实际启动 release CLI，检查 269 页前缀、500 页数量、270 页动作及下一边界。
- `verify_story_layers.py --left-excursion --stationary-brackets --vertical-dip --rightward-motion --actor-filter --games-selected 0` 使用独立 DAT 解码、源内静态图层重放和 Pillow 检查最终场景；不冒充完整原版脚本 VM。
- `verify_story.py --games 0 --until-boundary --movie-completion secondary` 在真机从标题开始，用实际按钮推进到边界。电影明确点击跳过，不声称本批自然播完。
- `verify_motion_frames.py --include-left-excursion` 要求六处动作捕获齐全，逐帧独立重建。第 270 页必须有不同的中间画面、首末像素一致、Y 不变、X 位于 `[920,1120]`；其他五处动作及 BGM 交错顺序继续检查。

Android 生命周期代码未改动，本批验证正常结束及错误边界的 VM 释放；后台取消沿用 Batch 20 已验证的共享通道，**本批不重新声称做过新动作的真机后台取消测试**。新动作提前翻页回位有本批单元测试证据。所有游戏资源、捕获帧、截图和 APK 只保留本地。

## 真机结果与最终核验

`excursion-batch21-native.json` 记录原生 ARM64 真机的 500 页完整有界回归。页面元数据、原脚本文字与 PNG 全部通过；291 个音频请求通过原始 DAT 哈希及播放器事件核对，`excursion-batch21-audio-evidence.json` 复核通过，没有依赖终止区间豁免的音频条目。电影播放 193 帧后明确点击跳过，再继续章节。

六处动作共捕获 43 帧，全部通过独立原图/Pillow/原版曲线逐字节对照，见 `excursion-batch21-frames.json`。新动作第 270 页采样为 0、17、69、116、163、211、250 ms，对应 X 为 1120、1077、967、921、942、1025、1120；Y 始终为 360。首末帧完全一致，中间画面确实不同，图层重叠和 Alpha 合成通过。125 ms / X=920 的理论峰值由核心测试覆盖，不声称手机恰好采到该时刻。

500 页最终场景与 25 张演出目标图通过独立图层/Pillow 检查，另有一次屏幕震动的中间帧通过既有独立核对。第 270、271、500 页实际 UI 截图确认横屏与对白显示正常。第 271 页没有动作残留，角色 1 稳定锚点仍为 `[1120,360]`。

第 270 页逻辑时长 250 ms，宿主 begin→finished 记录为 290 ms，包含合成、传输和调度开销；不声明固定帧率或动态原版时间轴一致。到达 `012603:211` 后 VM live bytes=0，结束会话后音频资源释放完成。

APK SHA-256：`9ccba6db463f3431e9501a98f43987c0a90a3e89014e5c0d0eff7884fe1d5dd1`。`excursion-batch21-final.json` 汇总同一构建、严格桌面复跑、真机、独立像素与音频报告的一致性及测试日志哈希。旧 Batch 20 的 39 帧捕获用更新后的校验器重放通过，历史报告未改写。本批未运行模拟器或其他三部，仍不代表完整游戏兼容。
