# Batch 41：文字边框、粗体与设置动态预览

## 原版依据与实现范围

BLESS 原始 `system/config.nut` 将 Bold、Border 绑定为二选一开关。第二页每次重绘使用 SAMPLE 的 BoxOpacity，并用字号 22、白色、可选黑色边框，在 TSAMPLE 坐标绘制脚本中的固定示例文字；它不是根据 TextSpeed 逐字播放的示例。`message.nut` 对剧情正文及姓名使用同一 Config.Bold / Config.Border。

本批将开关接入原有共用配置，预览直接读取本地 DAT 内配置脚本的示例字面量和 MNG 坐标，没有将 BLESS 示例文本写死在 Rust 中。该解析器目前支持已观察的静态、无转义字面量，遇到其他表达式明确报错。设置变化立即重新合成预览；标题设置和剧情设置共享绘制路径。

预览与对白使用相同的 Rust 字形布局、光栅化和边框绘制函数。常规字体的旧路径保持不变；粗体在现有 Noto 常规字形覆盖率上向右扩展一次 1 像素，再生成边框，不改变字符 advance。模拟器没有独立 Noto CJK 粗体文件，因此这是一种明确的宿主合成粗体方案，不是已证实与 Windows GDI / MS Gothic 完全一致的粗体算法。字体替代和原版逐像素差异仍是已知边界。

标题宿主新增只读字体安装操作；剧情预览和对白通过 Arc 共享一个已校验字体对象，不复制两份字体数据。字体字节、示例文本、字形和图像仍受既有输入/内存上限约束。未引入新的平台图形 API 或第三方字体分发。

## 配置与返回剧情

配置升级为 NKCF v4：5 字节头 + 原有八项 + Bold/Border 两字节 + 十个快捷键 ID，共 25 字节。继续读取 v1/v2/v3；旧载荷缺少的字段保留当前游戏默认/现有值。两个开关只能是 0/1，全部输入先校验再写入 VM。SharedPreferences 键保持不变。

从剧情设置返回时，透明度、边框或粗体任一变化都会从原始消息框资源重建当前页渲染缓存；保留当前对白 token、已显示字数、字形排列和脚本状态，不重新发出语音或场景请求。Android 返回键继续先取消弹窗、再返回剧情。

## 验证口径

新增 `verify_story_settings.py --text-style-check`，对四种样式同时检查预览图像和实际对白图像：结果区分四种组合、粗体覆盖增加、字形排列不变、标题与剧情的同配置预览一致、透明度预览变化、非默认样式重启恢复及原配置恢复。随后继续既有 57 页、后台、BGM、角色动作和返回键回归。

旧快捷键验证器继续独立核对各页静态资源与控件；第二页 SAMPLE 区域改为明确排除，由新的动态样式验证覆盖，不再将旧的静态示例图当成新预览的正确结果。

仅使用 emulator-5568（x86_64 / libnb.so）的 ARM64 翻译执行，不是真机。未进入 CG 或回想页面。源素材、字体及截图不提交到仓库。结果见 `research/text-style-batch41-emulator.json` 及同批 checks 文件。

## 实测结果

四种组合在预览和实际对白中均有不同的 PNG 结果；粗体的白色覆盖像素增加，四种组合的字符排列坐标相同。标题/剧情预览一致，0/127/255 透明度预览可区分，Bold=1、Border=0 在重启后保留，测试结束恢复原配置。

默认常规字体加边框的第 1 页对白 PNG 与 Batch 40 设备产物逐字节一致（SHA-256 `32bd6f115b2e53918726633819ead2ba78df30de2167debaf2f7812c81248e96`）。这是已有默认路径的回归证据，不是原版 Windows 粗体像素一致性证明。

随后完整通过 57 页剧情元数据/场景 PNG 基线、已有文字返回、Android 返回键层级、后台恢复、BGM 同播放器恢复、角色动作完成及 VM 清理。最终设备流程没有 UI 或 ADB 读取重试。138 个顶层 Rust 测试、7 次隔离原生安全探针、Clippy 严格检查、17 个 Python 测试及 NDK ARM64 构建通过。该覆盖不等于全篇通关。
