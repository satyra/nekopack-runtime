# Batch 36：修复设置第五页图层混乱

用户反馈第五页显示混乱，真机复现了整列快捷键候选文字覆盖主页面、F3～F12 槽位却没有名称的问题。这是 Batch 35 的渲染错误；此前验证了第五页能够打开，但没有验证其完整画面。原来的音量页像素对照不能证明第五页正确。

## 根因和修改

`config5.mng` 同时存放设置主页面、快捷键名称和 `ShortCutsWindow` 的弹出列表图层。此前 `settings.rs` 绘制全部普通状态 sprite，错误地将弹出列表的 SAVE、LOAD、RESET、DELETE 等候选项画到主页面上。它也没有执行原版第五页专用的名称定位规则。

本批按 `ViewConfigPage` 和 GUI 实际绑定范围限制第五页的可见普通控件：翻页、关闭/默认标签、CenterKey 和 SpaceKey 单选。弹出列表图层既不绘制，也不注册为当前页的命中区域。资源表的后项覆盖规则保持不变；重复名称并不是这次画面混乱的根因。

从当前 VM 的 `Config.ShortCuts[2..12)` 读取十个名称，取相应无前缀文字图层，以 F3 热区为原点，按目标 F3～F12 热区的位置差绘制。这对应原脚本的槽位平移规则，没有硬编码十个显示结果。空绑定不绘制文字，未知名称和位置溢出明确报错。

快捷键编辑仍未接通；本批只修复主页面显示及隐藏弹出列表的命中问题，没有启用原版弹出列表。

## 验证

- PGKM10 原生 ARM64 真机重新安装验证，APK 哈希见 `research/shortcut-page-batch36-phone.json`。已查看实际手机截图确认各格名称和页面布局。
- `platforms/android/verify_shortcut_page.py` 独立提取原始 PNG（逐块检查 CRC），依据原设置脚本的默认绑定和原始热区位置合成第五页。修复前画面有 **67,348 个像素**与该基准不同，修复后不同像素为 **0**。这是与原始素材和脚本绘制规则的对照，不宣称原版 Windows 动态截图完全一致。
- 核对十个实际绑定名称，以及弹出列表候选项不出现在页面命中区域中。
- 第五页 → 第四页 → 第五页、第五页 → 第三页 → 第五页，返回后 PNG 完全相同；Home 后恢复也保持画面。
- 点击尚未支持的 F3 编辑只提示未接入，不打开弹出列表、不改变配置或画面。
- 未恢复默认或修改用户配置；回归前后环境音量保持 55%，其余七项配置也保持原值。手机停留在修复后的第五页。
- 135 个 Rust 顶层测试、7 次隔离原生安全探针、严格 Clippy 和 NDK ARM64 构建通过。新增单元测试覆盖弹出列表隔离、主页面控件保留和槽位位置差。

只涉及共用 Rust 设置渲染及验证脚本。未改剧情、音频或存档语义，未读取 CG／回想详细内容。截图和原始素材留在被忽略的本地目录，未提交到仓库。
