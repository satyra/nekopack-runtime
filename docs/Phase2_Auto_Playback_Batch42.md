# Batch 42：Rust 自动播放与 AutoSpeed

## 行为依据

依据 BLESS 原始 DAT 中 `system/message.nut` 的自动分支：

- 入页捕获 `AutoSpeed`，无语音时等待 `3000 - AutoSpeed * 25` 毫秒；计时从正文完整显示开始。原脚本以 `end = timer + 1` 标记完成，使用严格大于比较，本实现保留该边界。
- 有语音时以语音结束为 NEXT 条件，不叠加 AutoSpeed 延迟。语音先结束而文字未完整时，先显示完整文字，下一帧才允许离开。
- 普通 NEXT 不关闭自动模式。宿主提供明确的“自动：开／关”按钮。
- TextSpeed 和 AutoSpeed 在入页捕获；KeepVoice 在推进时读取。更改设置不重新播放当前语音，也不重置当前页计时。

这是原始系统脚本的静态语义依据，不是本批对 Windows 原版可执行文件所做的计时测量。

## 共用运行时与 Android 边界

Rust 的 Reveal 判定逐字显示、完整显示时间、自动等待和一次性推进许可。StorySession 保留自动模式跨页状态；最终仍须以对应页面序号执行 ACK，轮询不直接改变脚本 PC。重复推进许可、旧页面 token 和设置期间输入均被拒绝。

Android 仅报告当前语音通道是否已经释放。正常播放完成回调释放该播放器；后台或音频焦点丢失只暂停并保留播放器，因此不会因 `isPlaying == false` 误报结束。所有设备播放器访问留在主线程，Rust 调用继续串行在现有 worker 上执行。

自动模式下全文显示后继续请求帧。请求代次在每次发送时递增，取消旧的延迟轮询；切换自动模式先挂起该页请求，再修改核心状态、恢复请求，避免开关与下一帧竞争。设置及 Activity 后台继续使用既有 active clock，暂停时间不计入自动等待。

暂停保证针对原版设置页；宿主旧的“音量／文字（当前会话）”调试弹窗仍是实时调节界面，不冻结剧情。

当前自动开关属于共用 StorySession 的会话状态，不持久化；它不是完整原版 GUI/ShortCut/选择肢系统的实现。headless Host.auto_mode 尚未作为剧情模式的共享控制入口。后续接入选择肢及快捷键执行时须将其接入同一核心状态，并验证 KeepAuto 等规则，不能维护第二套独立自动状态。

## 配置

NKCF v5 为 26 字节：5 字节头、原有十项、AutoSpeed 一字节、十个快捷键 ID。AutoSpeed 范围 0..100。继续读取 v1/v2/v3/v4；旧格式没有的字段保持已有值／游戏默认值。SharedPreferences 键不变。原版设置第二页自动速度控件通过共用字段绑定启用，保存、恢复默认和重启读取共享现有配置链路。

## 验证范围

新增核心测试覆盖 0/50/100 速度与严格时间边界、关闭自动、语音先结束的两阶段推进、语音未结束不推进、重复 ACK 和过期事件。`verify_story_settings.py --auto-check` 在既有 57 页回归后，从原始 DAT/SAF 标题入口自动运行至第 56 页：对白推进不得来自模拟点击，分别检查有声／无声条件，包含后台、设置、角色动作和配置重启恢复。开场 movie 仍由其“返回剧情”按钮结束，不用自动模式跳过视频，也不改脚本 PC。

仅测试 BLESS，设备为 emulator-5568，x86_64 / libnb.so 上的 ARM64 翻译执行。不代表 ARM64 真机、全篇通关或所有游戏兼容。未访问 CG／回想详细内容，游戏资源与截图不提交。

## 最终实测结果

最终 APK SHA-256：`8ec9ff47a2a0f1a43b7548d65ad8e3f08057fdbe8d8a27e4cc4c5bc38ab744af`。

- 57 页既有剧情元数据及场景 PNG 基线通过；原版设置返回、后台冻结、BGM 同播放器恢复及角色动作回归通过。
- 自动模式完成 55 次无点击推进：19 页语音分别有真实设备播放完成回调，36 页无语音符合文字完成后严格超过 501 ms 的等待条件（AutoSpeed=100）。核心单元测试另覆盖 0/50/100。
- 第 56 页自动进入原版设置时角色动作已运行 33 ms；设置及后台期间保持同一脚本状态。关闭自动后停止自行换页。
- AutoSpeed=100 保存并重启恢复，测试结束恢复原值 50 及其他原配置。所有测试会话正常关闭，VM live bytes=0。
- 142 个顶层 Rust 测试、7 次隔离宿主原生探针、17 个 Python 测试、fmt、Clippy 严格检查及 NDK ARM64 构建通过。
- 最终流程遇到一次 UiAutomator 空根节点，按既有有界重试重新读取后通过；没有 ADB 读取超时重试。
