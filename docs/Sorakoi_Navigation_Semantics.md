# 空恋 NEXT / BACK 技术语义

本记录只涉及原版 system 技术脚本与原生 API，不包含剧情、选项正文或图像。

## 原脚本契约

- `shortcut.nut`：NEXT 绑定 `ID_SKIP2`，BACK 绑定 `ID_BACK`。两者仅正常模式、路线内可用；NEXT 再检查 `IsEnableSkipNext()`（`var["NEXT無効"] == 0`），BACK 再检查 `IsEnableSkipBack()`（回退栈非空）。
- `system.nut`：NEXT 经原确认框后设置 `MegaSkip=true` 并调用 `ClearImage()`；BACK 经原确认框后调用 `SkipBack()`。NEXT 不是普通下一页，BACK 不是历史窗口。
- `dialog.nut`：只有 `(name in Config.Dialog) && !Config.Dialog[name]` 才省略确认。缺失的键默认仍确认；当前 DIALOG_TAGS 没有 BACK，并不表示 BACK 可跳过确认。安卓结构化确认配置使用同一默认规则，取消不派发导航。
- `message.nut`：MegaSkip 状态仍将消息加入日志，但跳过消息显示。
- `select.nut`：进入选择时若 MegaSkip 则调用 `RestoreSkipState()`，随后清除 MegaSkip。确认有效选项时，在返回选项 ID、执行分支之前调用 `SkipBackSave()`。
- `SkipBackSave()` 保存消息日志长度与完整 `SaveBlob()`；`SkipBack()` 取栈顶，截断消息日志，加载快照，再弹栈。因此必须恢复尚未完成的选择请求，而非上一对白或页码。

## 原生 API 的定点核查

核查对象为本地原版 `sorakoi.exe`，仅读取 PE 技术字符串引用与相应函数指令。

- `RestoreSkipState` 注册回调位于 `0x57f4d4`，仅调用 `0x4561b0`。该函数检查 `0x7a2644 + 0x98`，使用资源目录字符串 `sound/bgm`（VA `0x745dad`）调用 `0x465748`，随后调用 `0x696d60`。这证明该 API 的恢复工作属于 BGM 通道；未发现变量、脚本栈或场景快照恢复。缓存各字段具体名称尚未完全还原。
- PE 中不存在 `SaveSkipState` 注册名，不据此臆造同名脚本 API。
- `ClearImage` 注册回调位于 `0x57c6a4`，调用 `0x5cc060` 与 `0x5fd0e0`；后者遍历九个 actor 结构。不能据名字将其解释成清除剧情变量或路线控制流。

## 运行时实现

共用行为按挂载脚本契约接通，不按游戏名分支。NEXT 跳过中间呈现，保留执行的变量、图层、历史和音频状态，到选择处恢复最终 BGM 与最终画面。BACK 使用私有 `NKSC` 选择快照，公开存档 `NKSV` 仍限定对白；两类快照不能混用。快照复用完整场景、VM、动作、持久音频及消息历史序列化。正常读档清除旧回退栈。 安卓导航确认沿用宿主弹窗，是否显示及取消/确认的行为按原 ViewDialog 规则处理；此次没有将该弹窗描述为原 dialog.mng 的绘制复现。

合成测试覆盖：选择前快照、选择分支改变量、历史新增、场景与 BGM 改动，然后 BACK 恢复选择前变量、场景、历史、音频，音频确认后再次呈现未完成选择；不执行已选分支。侧栏测试覆盖 NEXT/BACK 可派发、原 Update 的使能规则与临时宿主覆盖恢复。

## 共享视觉资源组合

NEXT 实测触达 `.img #HK00&0000`。只核查元数据：原版 `image.dat` 的 `image/visual/HK00.mng` 为 entry 135，MHDR 为 1600×900，帧标题为 `0000`，位置为 `[0,0]`，没有 TERM 差分标记。该语法应选 MNG 命名帧，不能将完整组合串追加 `.png`。

`scene::read_visual` 对普通名称维持 PNG 与零偏移检查；`#container&part&part` 从同目录的 MNG 按名称查帧，再按顺序与帧坐标绘入 MHDR 画布。TERM 9999 差分标记复用既有 actor 图层的字节还原规则。当前观测需求为精确帧名，不臆造模糊匹配或跨容器附件语法。场景存档已内嵌视觉像素并原样保留名称，BACK 不重新将该名称当作 PNG 文件名。

### 视觉层 alpha

同一原版 HK00 帧只统计像素分布，不查看内容：1600×900 中 1,435,004 像素 alpha=255、4,996 像素半透明，alpha 范围 236–255。旧 `set_visual` 对半透明的拒绝与该真实资源冲突。视觉层保留原始 RGBA，按既有背景→actor→visual 顺序做 source-over；不将 alpha 强制为 255，也不人为指定黑白底。合成测试覆盖视觉层与背景混色、与 actor 混色、全透明保留下层，以及 checkpoint 后 alpha 与混色结果一致。

## Wipe 时长的原生 ABI

此次实际触达的 `.wipe WIPE011 0.5 fade` 暴露了原生处理器差异。旧 `Phase2_Visual_Wipe_Landscape_Batch10.md` 的“数字毫秒”结论对当时四部曲的原生处理器正确，不能将本次秒制扩展到旧包。

静态复核六份本地原 EXE，均只读取文件，没有启动它们：

- BLESS / BIRTH：`MillisecondsInteger`。两份 EXE 字节相同，WipeCommand 构造函数 `0x442F1C`；`0x4430B0` 调用整数解析 `0x504580`，结果直接保存，数字 `100` 表示 100 ms。
- BLACK：`MillisecondsInteger`，构造函数 `0x442E6C`。
- BRAVE：`MillisecondsInteger`，构造函数 `0x49ABC4`；`0x49B4F6` 调用整数解析 `0x5F68C0`，直接保存。
- ED：`MillisecondsInteger`，构造函数 `0x63E0A4`；`0x63F1C3` 调用整数解析 `0x6EFFB0`，直接保存。
- 空恋：`SecondsFloat`，构造函数 `0x41D068`；`0x41E17B` 调用浮点解析，`0x41E181` 乘地址 `0x422980` 的 float32 常量 1000.0，`0x41E187` 调用截断转整数。因此 `0.5` 表示 500 ms，整数 `1` 表示 1000 ms。

六份处理器都先按 token 的首字符作数字分类，再进入数值分支；没有参数或换算后的值不大于零时均回到 500 ms 默认值。空恋在 `0x41E87D–0x41E887` 执行此检查，所以显式 `0` 不是零时长；小于 1 ms 的正数在截断为零后也使用默认值。首字符不是数字的 token（例如 `.5` 或 `-1`）不能仅按宿主浮点解析成功就当作原生时长参数。旧整数解析在小数点处停止；这与新浮点秒制是不同契约。

PE FileVersion 的实测值分别为 BLACK `1.0.2.17`、BLESS/BIRTH `1.0.3.27`、BRAVE `1.0.3.30`、ED `1.0.4.4`、空恋 `1.0.4.57`。这些只是证据标记，未确定 ABI 切换的版本阈值。已查的原 system/config 源码没有显式时长 ABI 声明；画布大小、游戏名、PK02 magic 和标题函数都不能代替此声明。

`engine_abi::probe` 只读 PE32，通过 `WipeCommand` 类型名、Borland RTTI 与唯一 vtable 定位构造函数，再验证数字分支：

- 整数毫秒型必须识别整数解析的符号、十进制累积、数字边界与返回指令，且调用结果直接存入时长字段。
- 浮点秒型必须识别浮点解析包装、乘 1000.0 和改变 FPU 舍入方式的截断转整数指令，结果存入时长字段。
- 两型都检查同一个时长字段存在 500 ms 默认赋值。

探测不使用 EXE 名称、版本白名单、原生代码整文件哈希或画布参数。没有 `WipeCommand` 类型时返回 `None`；存在类型但码型未知、损坏或多重匹配时返回错误，不静默选择单位。安卓可将同目录原 EXE 当数据读取探测；只有 DAT 的旧入口保留既有整数毫秒行为，这属于旧入口契约，并不意味着已经从 DAT 证明了原生 ABI。秒制必须有探测结果或经过验证的明确元数据来源，且纳入存档身份以隔离不同语义。

验证：合成测试覆盖两种码型、错误乘数、损坏整数转换、损坏截断转换、歧义 vtable 与未知类型；另一个可选本地测试实际读取上述六份原 EXE，结果全部符合已确认 ABI。没有查看图片或剧情正文。原处理器反汇编与对比仅保留于本地 `.local/sorakoi-import/analysis/wipe-*.txt` 与 `wipe-generation-comparison.json`。

### RTTI 归属与注册链的交叉复核

Borland VMT 的实际布局是 `[type_info, 0, 0, parse, execute]`；类型指针在当前方法表前 12 字节。连续数据里看到的 `[parse, execute, type_info]` 不能当成当前类的三元组，末尾的类型指针属于下一张方法表。此次曾出现该歧义，最终以脚本键→对象→VMT 的真实注册链交叉核查，保持探测器正确的 type-reference `+12/+16` 方法定位方式。

空恋原版注册链：

- `.wipe`：`0x4024B7` 将 VMT `0x743F90` 赋给对象 `0x7A25F4`；`0x4024C2` 压入该对象，`0x40252A` 起构造 `wipe` 键。该 VMT 的前置 RTTI 位于 `0x743F84`，指向 `0x418C5C` 的 `WipeCommand` 类型；parse/execute 为 `0x41D068` / `0x422984`。
- `.fade`：`0x401D1F` 绑定 VMT `0x743FA4`，`0x401D92` 引用 `fade` 键；前置类型为 `0x418BFC` 的 `FadeCommand`，parse/execute 为 `0x426384` / `0x42891C`。
- `.page`：`0x402C58` 将 VMT `0x743F7C` 赋给对象 `0x7A2604`，`0x402CD4` 引用 `page` 键；前置类型为 `0x418CBC` 的 `PageCommand`。其短执行函数是 `0x41D044`，不能用它推断 `.wipe` 没有参数或时长。

同样逐一核对了旧五份 EXE 的注册键与 VMT，均与探测器选中的 WipeCommand 参数解析范围一致。静态注册证据保存在本地 `wipe-registration-binding.json`。新增合成测试专门在 Wipe RTTI 前后放入无时长解析的相邻类方法，确保不会把前一类的方法与后一类的类型指针混配；4 项合成测试及六份真实原 EXE 探测再次全部通过。

另行确认 `.fade` 的单位：空恋 `0x42737C` 解析浮点、`0x427382` 乘 1000 后截断；BLESS 与 ED 则先作整数解析，再以整数运算乘 1000。两代 fade 都以秒为单位，但旧版在乘法前丢弃小数，新版在换算毫秒后截断。因此 `.fade 1.5` 在旧版为 1000 ms、新版为 1500 ms；无参或最终非正值仍使用 500 ms。该结论与 `.wipe` 的旧毫秒/新秒区别分别记录，不混用。


## 实际跳转发现的共享指令边界

- 本地标签与条件 `.goto` 根据当前脚本词法结构重建分支终点，不按具体文件补跳转。
- 选择分支的无空格 `?变量=变量+1` 使用共用整数表达式解析；已有按位 OR、相等比较也走同一入口。运算优先级、括号、短路、整数溢出及嵌套上限有合成测试，不把实际分支中的加分指令省略。
- 原 `macro.nut` 的 `SoundHook` 是原生音频参数解析的一部分：`0x434049–0x434056` 调用并保存映射结果，执行阶段 `0x4451BF` 才检查 MegaSkip。BGM/ENV/SE 请求先执行原 hook，跳转期间也保存规范资源名；`RestoreSkipState` 直接恢复该名称，不再次转换。没有针对具体别名建立运行时替换表。
- 无参 BGV 停止两条独立背景语音通道，不错误停止 ENV。带参数 BGV 的完整选择器语法不在此次完成范围。
- MegaSkip 省掉不可见转场的画布/PNG/过渡对象构造，仍解析指令、更新图层/遮罩/动作及音频状态；选择处生成最终画面。现有滤镜提交边界保留，但没有据此声称已完整复原原生滤镜缓存内部机制。
- 当时 `.movie op.wmv` 的脚本请求与 MegaSkip 路径已允许 WMV 文件名，但解码器仍只有 MPEG-1/MP2；该轮跳转越过 OP，不代表正常 WMV 播放已经实现。后续共用 ASF/WMV 解码及原脚本完整播放、自然返回的验证见 [WMV_Runtime_Playback.md](WMV_Runtime_Playback.md)，两轮证据分开保留。

模拟器测试只传回排版几何、选择检查点、音频/剧情文本哈希与技术状态。控件定位在设备端过滤可访问性 XML，不取回选项正文，不读图或回想正文。
