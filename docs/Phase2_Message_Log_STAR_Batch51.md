# Batch 51：原版消息日志与 STAR 提示音

## 原版依据

本批只研究 BLESS 的消息日志、系统提示音和相关存读档行为，没有读取 CG／回想详细内容。`research/verify_original_message_log.py` 对本机原版 EXE、原始 DAT 条目和已导出的系统脚本重新核对；脚本导出内容与原始 DAT 解码后逐字比较。证据见 `message-log-batch51-original.json`，包括源码行定位、资源摘要、27 个 log.mng 精灵位置和 13 条指令断言。这是静态证据，不是本批重新操作 Windows 原版获得的动态时序或听感结论。

`message.nut` 的 ViewLog 显示四条记录，初始位置为 `max(0, MessageLog.len()-4)`，滚动按一条移动。记录包含姓名、语音、头像标识和文本；正文生成时追加，InRestore 时不追加。点击有语音的记录调用 PlayVoice；退出日志没有停止 BGM 或语音的指令。SaveInfo 保存并恢复 MessageLog，槽位预览 Get 不替换运行中的日志。BLESS 的 log.mng 没有 FACE 精灵，也没有关闭按钮，本批不虚构这些资源。

QuickSave／NormalSave 在 InRoute 检查后调用 `sound("STAR")`；QuickLoad／NormalLoad 在读取存档前调用，因此读档失败也会触发提示音。EXE 的 0x4468cd、0x4468f7、0x446918 分别引用 `se_%s`、`sound/se`、`VolSYS`，独立系统声道随后启动播放。正确资源为 sound.dat 第 79 项 `sound/se/se_STAR.ogg`，不是剧情 SE 音量类别。资源为双声道 44100 Hz，92416 帧，约 2.096 秒。

## 实现与状态约定

Rust `message_log` 管理记录、原版 MNG 绘制、滚动命中和语音资源读取。Android 使用原有 TitleView 做触摸坐标映射，并提供返回键／“返回剧情”适配入口；F9 使用当前用户快捷键配置，右侧 Log 使用现有浮动菜单。没有另建 Android 日志状态或剧情 VM。

日志作为当前对白的模态界面：停止自动／快进，冻结对白和角色动作时钟，保留原对白对象。关闭时先核对 Rust 当前页面包与打开前完全一致，再恢复原界面。BGM 持续播放；点击历史语音替换现有 voice 声道，关闭日志不重新播放原对白语音。应用退到后台仍暂停播放器，返回日志时只恢复音频，剧情时钟保持冻结。

STAR 使用独立 system 声道和 Config.VolSYS；历史语音使用 Config.VolVO。UI 音频采用宿主独立负 token，不确认或推进脚本待处理命令。读档清理旧剧情声道时保留当前 STAR，销毁整个会话时全部释放。音频调度与被冻结的剧情时钟分开，避免日志内语音或提示音等待剧情恢复才启动。

运行器存档升级为 NKSV2，在原有数据后加入日志。恢复先检查日志最后一条与待执行对白、说话者和语音一致，再提交状态；重建当前对白不重复追加。继续读取 NKSV1，旧格式没有历史日志，所以仅从恢复的当前对白重新建立一条记录；无法重建旧文件从未保存的历史。仍不兼容 Windows 原版 `.sav`。日志有 32768 条／8 MiB 文本预算，单条姓名和正文各限 4096 字符，超过边界明确报错，不静默截断。

## 验证口径

最终结果与 APK 摘要以本批 `research/message-log-batch51-*.json` 为准。`verify_story_saves.py --quick-check --log-check` 验证真实 DAT／SAF 剧情基线、日志首页／末页与滚动、历史语音、后台切换、普通和快捷存读、标题读档以及 NKSV1 兼容。返回日志后对比当前对白包、场景 PNG 和文字显示状态；历史条目逐条对照既有剧情基线。

`verify_message_log_evidence.py` 独立重读设备文件：核对 STAR 次数与存读操作次数、原始 DAT 音频摘要、实际 playing 和播放位置进度、VolSYS 增益、日志开关前后的 BGM 播放器身份、语音重播继续或自然完成，以及退出后的 VM／缓存清理。STAR 走 MediaPlayer，播放位置不是 AudioTrack PCM 播放头观测，两者分别记录，不混用。`verify_story_save_evidence.py` 继续检查恢复音频资源、旧剧情 token 回调隔离和快捷槽索引。本批不以退出码或编译通过替代状态断言。

首轮设备回归暴露 UI 音量返回整数与 Squirrel 桥文本返回契约不匹配，修正为显式整数校验和 tostring，并新增覆盖 VolSYS／VolVO 及无效值的 Rust 测试。失败日志保留在本机 `.local`，不计入通过结果。该中断曾留下测试音量 17；最终回归显式恢复本轮前的 50，并记录该恢复值。

补强验证时还校正了两处测试口径：返回剧情后 elapsed_ms 和 voice_finished 可以正常变化，检查改为日志内文字状态冻结、返回后对白序号／内容／显字数量／完成与推进标志不变；STAR 使用 MediaPlayer，应检查其播放位置而非要求不存在的 AudioTrack 播放头事件。独立检查仍要求真实播放事件、资源摘要和音量匹配。

最终 APK 为 `bd482065c25ffabadbd89ee3ed980725aef045f7e5ee8b991c30f2f03b41a793`。主回归通过 57 页基线和 9 次日志往返，覆盖普通／快捷／标题读档后的日志恢复、继续对白时追加一条以及 NKSV1 当前条目恢复。独立核验 29 次 STAR 均有匹配资源、正确增益和播放位置进度，4 次历史语音重播在日志关闭后继续原播放器；各主回归会话结束后 VM 分配为 0、音频缓存为空。右侧 Log 触摸入口及“返回剧情”按钮另有独立回归，已查看实际设备截图，未提交游戏图片。

161 个顶层 Rust 测试、7 次隔离原生探针、17 个 Python 测试、fmt check、Clippy all-targets / deny warnings、验证脚本语法检查以及 NDK r27d / API 23 ARM64 构建通过。最终报告和日志摘要集中于 `research/message-log-batch51-checks.json`。

另行完成现有设置页 57 页兼容回归：部分对白暂停／恢复、后台模态、音量修改后恢复同一 BGM 播放器、返回后继续角色动作均通过；动作在 41 ms 处暂停，返回后完成。设置最终恢复为测试前值（包括 VolSYS=50）。主回归出现两次 UIAutomator 空层级，经既有限次重试恢复，没有跳过断言；设置页回归没有层级或传输重试。本批没有重跑完整自动／快进专项。

## 边界

- 模拟器 emulator-5568：x86_64 + libnb.so 的 ARM64 翻译执行，本批没有真机结果。
- 日志使用宿主安装字体，不宣称与原版 MS Gothic 逐像素一致；未实现日志 PAGE／CLICK 附加音效。
- 验证播放器状态、资源身份和播放进度，没有本批人工听音确认或原版听感对比。
- 音频读档仍按资源／声道／循环属性重启，不恢复采样位置；旧格式日志仅有当前条目。
- 此实现针对已确认的 BLESS 资源布局，不宣称完成所有 NekoPack 游戏的日志兼容。
