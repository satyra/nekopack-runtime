# Batch 38：原版设置页对话框透明度

## 实现范围与依据

接通第二页 `BoxOpacity` 滑条及两端按钮。原始 `system/config.nut` 定义 `OPACITY_MAX=255`，默认值为 `255*3/4=191`，并以 `VolumeBar(..., OPACITY_MAX)` 绑定控件。Rust 按 0～255 的范围计算触点值，音量和文字速度仍使用 0～100。滑条图像位置沿用原始控件坐标。

原始 `system/message.nut` 在透明度小于 255 时，先对 NAME/TEXT 执行 Clear/Blt，再绘制文字；255 时保留原图。现有共用 `DialogueRenderer` 已实现此流程，本批让设置值通过同一个标题 VM 进入 StorySession，安装字体时读取配置，不新增 Android 专属渲染算法。透明度控制背景框，不使正文随背景一起消失。

第二页 SAMPLE 仍是既有静态图像；动态示例文字及示例透明度预览未接通。当前通过标题设置后进入剧情生效，不宣称已实现剧情中打开原版设置页或实时重建正在显示的对白框。

## 配置兼容

新增 `NKCF` v3，长度 23 字节：5 字节头、原有七项、1 字节 BoxOpacity、10 字节 F3～F12 动作 ID。继续接受 v1（12 字节）和 v2（22 字节）；旧格式没有的字段保留当前 VM 值，正常新启动为游戏默认值。v2 的快捷键偏移与 v3 分别解码，避免将旧快捷键 ID 误当透明度。

保持原 SharedPreferences 键以发现旧数据；下一次写入升级到 v3。导入先校验完整长度和所有字段，再修改 VM。恢复默认包含透明度；单独修改透明度保留音量、文字、语音保留及快捷键。

## 验证范围

仅使用 emulator-5568：x86_64 宿主通过 libnb.so 翻译执行 ARM64 APK，不是真机验证。回归入口为原始 DAT、SAF 和正常标题设置流程。未进入 CG 或回想页面，也未读取其详细内容。

设备结果见 `research/opacity-batch38-emulator.json`，工作区检查和 APK 哈希见 `research/opacity-batch38-checks.json`。扩展既有快捷键验证器的 `--opacity-check`，在相同流程中核对五页设置、透明度持久化、剧情对白框和快捷键回归；原有历史报告保持不变。

验证过程的一次失败：最初把整个 TEXT 区域视作纯背景，透明度 0 时比较不相等。检查实际几何发现 NAME 与 TEXT 顶部重叠 5 像素，零正文字符帧已经包含姓名字形。验证器改为比较姓名栏下方的正文背景，并独立确认完整正文帧相对零字符帧产生变化；没有修改渲染结果来迁就测试。首次失败日志保留在本地，并在检查摘要记录哈希。此次像素等式基于此前确认的原生 Clear/Blt 算法，不是新的 Windows 原版动态截图比对。

## 本批结果

- 透明度 0、127、255 均通过实际触摸修改，关闭重启后数值一致。进入第一段剧情后，宿主收到相同 opacity；姓名栏下方的正文框背景与原始资源及已验证 Clear/Blt 公式逐像素一致，正文仍可显示，场景 PNG 与既有基线一致。
- 五页设置图像、快捷键弹窗、十个槽位、十种动作、清除/取消/拖出、后台返回及快捷键重启保存通过。完整回归恢复透明度 191 和测试前快捷键，其他配置保持不变。
- 从标题进入前三页剧情的元数据与场景 PNG 和既有基线一致；明确关闭后的 VM 追踪存活字节为 0。
- 136 个顶层 Rust 测试、7 次隔离原生安全探针、Clippy 严格检查、17 个 Python 测试及 NDK r27d ARM64 构建通过。最终设备流程遇到四次 UiAutomator 空根节点，限次重试后取得当前界面，未跳过断言。

上述覆盖不等于全篇通关；快捷键目标动作与动态设置预览的未完成范围仍保持明确。
