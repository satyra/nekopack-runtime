# NekoPack 脚本分析

## 可确认的结构

Niflheim 的文本提取器用 CP932 读取 `.txt`，将 `@ ; . ? #` 开头行排除出对白提取，对冒号行特殊处理；回写时命令行仍 CP932，部分文本改为 CP936。它提供文本分类线索，**没有定义执行语义**，不能直接充当 lexer/parser 规格。[N3]

本次直接解密本地 DAT 的 script/system 条目，按 ASCII 字节观察句点命令，不解码或提交对白内容。BLACK and WHITE script.dat 有 254 条；BLESS of DRAGON system.dat 的 script 目录有 174 条；BIRTH for YOURS 为 159 条，patch101 另有 32 条；BRAVE or SLAVE 为 203 条。条目数不是可执行脚本文件数，也不代表全部文件都可解析。[L1]

跨基础包和补丁观察到 `.img`、`.img0`–`.img9`、`.imgx`、`.fade`、`.wipe`、`.bgm`、`.env`、`.se`、`.call`、`.load`、`.sysload`、`.select`、`.case`、`.switch`、`.loop`、`.var`、`.def`、`.end`、`.movie`、`.staffroll` 等命令 token。计数保存在 L1 各包 dot_command_tokens 中；匹配表达式仅覆盖 ASCII 点命令，不覆盖其他语法，补丁与基础文本有重复，不能拿频率当覆盖率。[L1]

## 未知语义清单

补充静态证据：BLESS 的 system.dat 中存在可按 CP932 读取的 `.nut` 系统脚本，包含 class、function、local 等 Squirrel 风格语法。config.nut 的 ViewConfigPage（111–139 行）选择 config/config1 素材并绑定控件，gui.nut 的 RadioButton（114–130 行）维护选项状态。不能因此认定具体解释器版本或完整语言语义。已用这些调用关系指导一次静态界面重建，详见 [画布增量](Phase1_Canvas_Increment.md)，尚未实现脚本执行。

- 词法：注释、转义、字符串边界、多行语句与混合编码的完整规则未知。
- 控制流：call/load 的栈和返回行为、条件短路、标签作用域、分支匹配与 loop 终止规则未知。
- 变量：类型、作用域、默认值、持久化、表达式优先级与数值转换未知。
- 调度：命令阻塞条件、并发脚本、等待动画/语音的机制未知。
- 文本：冒号字段语义、说话人/语音对应、文字排版控制需原版验证。
- 系统：setup/start/title/story 是上游候选文件名，真正入口和启动顺序未知；不能按名称猜入口。[N2]
- 存档：PC 指针、栈、变量、场景与全局解锁信息的序列化及恢复时机未知。

本机旧移植工程已有 Ren'Py 转换规则，但这是另一个项目中的实现选择，不是原版语义证据，也不能继承其“可运行”状态作为本项目验证。

## 下一步实验设计

1. 按游戏文件 SHA-256 与补丁集合固定样本，分离原版/汉化执行文件及字符编码；保存原始字节，不通过 lossy decode 掩盖问题。
2. 从本地文本确定入口候选与调用图，记录“包 hash + 条目 hash + 行号/字节偏移”；公开报告不含对白全文。
3. 运行原版，以输入和时钟为基准记录菜单、场景、音频、分支与存读档行为，逐指令做可重现最小实验。
4. 对每个命令建立：语法、参数类型、状态变化、阻塞/完成事件、版本差异、证据与未解问题。
5. 先实现只解析和报错的 AST，再在证据支持的子集上实现 VM；未知语句报告样本、脚本、位置和 token 后停止。

## 覆盖率定义（设计）

分别报告 token 发现率、语法解析率、语义实现率、原版轨迹一致率。分母必须来自固定样本全集，并把启动路径覆盖和全剧情覆盖分开。目前已实现 [有限启动 AST](Phase2_Bootstrap_Parser.md)，验证了四部曲 12 份脚本的 91 条语句；完整 parser、VM 和 `.nut` 执行尚未实现，没有可信的运行语义覆盖率百分比。
