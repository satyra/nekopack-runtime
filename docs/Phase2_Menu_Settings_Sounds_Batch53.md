# Batch 53：原版剧情菜单与设置页系统音效

## 原版依据

本批范围是 BLESS 的 `ViewMenu` 和 `ViewConfig`，包含标题入口和剧情内设置。`shortcut.nut` 的剧情菜单在打开和取消时播放 PAGE；选择有效命令直接进入目标功能，没有通用点击音。`config.nut` 在进入设置、实际切换页面和退出时播放 PAGE；同页边界、恢复默认值、打开快捷键选择框和 Android Back 取消选择不新增音效。`gui.nut` 的单选确认使用 OK，音量滑条及端点使用 CLICK；快捷键选择或 DELETE 使用 CLICK。

原版单选控件的 SELECT 来自鼠标悬停目标变化。当前 Android 接口只有触摸按下、移动、抬起和取消，本批没有把触摸按下伪装成鼠标悬停，也没有扩展标题 `.map` 或其它系统页面。

`verify_original_menu_sounds.py` 对固定 SHA 的原版 EXE、原始 DAT 中脚本与导出脚本、相关指令和音频摘要进行核对。PAGE、CLICK、OK 分别来自 `sound.dat` 第 35、84、87 项；CLICK 与 OK 字节相同，但事件身份仍分别验证。

滑条先以旧 VolSYS 发起 CLICK，然后写回配置并执行 `RestoreVolume()`。EXE 中 `sound()` 与 `RestoreVolume()` 对同一系统声道 `0x584640` 调用音量函数 `0x4c0478`；后者会更新活动播放对象的增益状态并记录时间。因此实现保留旧值起播与当前播放器应用新值两个步骤，不把旧音量固定到整段提示音。静态证据不能确定原版更新前是否已有旧增益采样输出，本批不宣称采样级或听感一致。

## 实现边界

Rust 在实际输入处理时生成提示音事件和触发时音量，随菜单或设置响应返回。Android 从同一个 Rust DAT 资源层取得原始 Ogg；JNI 只接受固定音效编号和合法音量。没有预解包素材、新的脚本 VM、存档格式或平台专用剧情状态。

Android 将每个 UI 音效的起播音量绑定到对应播放器的实际启动，启动后同步更新设置的新音量，避免异步准备期间被随后抬手响应覆盖。未起播的暂停请求恢复时也通过同一个启动入口。静音设置响应会更新当前系统声道。

设置页将“剧情暂停”与 Activity 后台暂停分开：设置期间剧情声道、角色动画和剧情时钟保持暂停，系统音效可以播放；Home 暂停所有声道；返回设置仅恢复允许播放的系统声道，关闭设置后再恢复原剧情。系统声道仍采用已有的单声道替换规则，连续快速输入可以替换尚未播完的提示音，不承诺每个触摸事件都完整播放。

## 验证方法与限制

`verify_menu_sounds.py` 通过真实 Android 输入检查标题设置、分页边界、单选确认、系统音量、快捷键选择、剧情菜单返回及 SAVE／LOAD／CONFIG。音量测试检查同一播放器的旧值起播和新值增益，并核验原始 DAT 摘要、播放进度、后台暂停和 VM 销毁。测试结束恢复应用偏好文件的原始字节。

现有 `verify_story_settings.py --menu-check` 检查 57 页剧情基线、部分显字冻结、角色动作冻结和继续、同一 BGM 播放器恢复，以及菜单和设置返回原对白。右侧菜单另行复测已有日志入口与 PAGE 音效。

设备为 emulator-5568，x86_64 + libnb.so 的 ARM64 翻译执行，不是真机结果。音频验证采用资源身份、播放器状态、增益和播放进度，不代替人工听音。本批不读取 CG／回想详细内容。

## 最终结果

最终 APK SHA-256：`e6deef3d6df317a05cbc6acae757d52ceeb71114a162ff6a9bc5d70d38b5b1d5`。

音效专项 35 项操作通过，记录 PAGE 19 次、CLICK 6 次、OK 1 次，均匹配原始 DAT 摘要并有正播放进度。系统音量 50→0→37→50 的三次变化均验证同一播放器先以旧值起播、再应用新值。Home 后两次稳定快照中 BGM 和系统提示音位置均不变；返回设置后翻页能播放提示音，BGM 继续暂停，退出设置后恢复同一 BGM 播放器。对白页、场景摘要和执行位置保持一致，快捷键在第五页验证持久化；会话关闭后 VM 分配为 0，音频临时文件为空，应用偏好恢复原始字节。

完整设置及菜单回归通过 57 页剧情基线，覆盖部分显字、设置期间时间排除、角色动作冻结和恢复、同一 BGM 播放器恢复、Back 先关闭弹窗再返回原对白。本轮没有重新执行完整自动／快进或所有存档兼容专项。

右侧浮动菜单的快捷存读档、普通存读档取消、设置返回和消息日志返回也通过；日志开关各一次 PAGE，系统音量为已恢复的 50，会话关闭后 VM 分配为 0。

162 个顶层 Rust 测试、7 次隔离原生探针、17 个 Python 测试、fmt check、Clippy all-targets / deny warnings、验证脚本语法检查及 NDK r27d ARM64 构建通过。原版静态证据、最终设备结果与构建摘要见 `research/menu-sounds-batch53-*.json`。

首次专项脚本使用了模拟器不支持的 `input motionevent`，改为真实 tap 后重新执行；另一次错误地将首页空快捷键展示列表与第五页绑定列表比较，已改为实际翻到第五页验证。两次均未生成通过报告。异步起播音量覆盖、活动增益未更新和标题冷启动音量初始化问题在最终 APK 验收前修复。UIAutomator 偶发空层级按已有有界等待重新获取，没有跳过功能断言。中间 APK 的回归不作为最终 APK 的结果。
