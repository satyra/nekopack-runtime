# Batch 19：BLESS `[]` 抵消位移与后续章节对白

本批在共用 Rust Runtime 中接通末尾字面量 `[]`，继续通过 Android SAF 读取原始 DAT。只用 BLESS 与 PGKM10 原生 ARM64 真机回归；Android 仍是交付主线，不改写原始脚本，不增加其他平台宿主。

## 原版依据

`research/verify_original_brackets.py` 对本机 BLESS 原 EXE 的指令及代码片段做校验，EXE 哈希与 Batch 17 原版证据一致。结果见 `brackets-batch19-original.json`。

- 符号解析函数 `0x43cea4` 每轮默认计数为 1。`[` 在 `0x43cff2` 从 `[ebp-0x58]` 减去计数，`]` 在 `0x43cffa` 向**同一个**累加器加上计数；不是两项依次执行的动作。
- `0x43d04f..0x43d05d` 把累加结果乘以 50，写入动作结构的临时水平分量 `+0x0c`。因此字面量 `[]` 的临时水平分量为零，永久位移也为零，不应表现为左右摇晃。
- 默认 duration 在 `0x4389a2` 设为 250 ms。符号解析成功后，`0x43974d` 仍提交动作；队列执行路径只检查 duration 是否为零，不因为所有位移抵消而丢弃该动作。
- `0x438640` 更新函数按 elapsed/duration 保留活动状态；零位移跳过插值分支，但在到期之前仍返回活动。继续沿用 Batch 17 对 `message.nut` / `Screen.Render` 的调度证据：动作与对白并行，不额外阻塞一次脚本 ACK。
- 新推进片段中存在清除角色后无位置参数重载。原清除函数在 `0x437176..0x437188` 把当前和基准 XY 全部归零；绘制时加画布中心。现有运行时移除图层后重载为中心坐标符合该路径，不需要补丁。

这些是特定原 EXE 的静态代码证据，不是动态原版屏幕对照，也不证明所有 NekoPack 版本的兼容性。

## 实现范围

`scene::plan` 接受末尾单个字面量 `[]`。带图像名称时仍执行换图，纯动作保留图层顺序；绝对位置与动作组合、其他括号写法、嵌套宏及同角色多项待执行动作仍按既有边界报错。

`Motion::stationary` 保持 XY 不变，输出 250 ms 的 Page motion 元数据。`StorySession` 继续复用既有 `page_frame` 和 JNI operation 8，Android 无需另写动作算法。静态 PNG 相同不能证明该动作已执行，因此验证必须检查 begin、中间采样、250 ms 末帧和 finished/cancelled 事件。

新增核心测试覆盖静止计时、帧请求不推进 PC、不改变缓存页面、时间倒退与过期页拒绝、提前翻页无需等待，以及锚点保持。workspace 中 Runtime 共 37 项测试通过；Clippy、格式检查、14 项 Python 测试通过。原有隔离测试中的显式忽略项不计作新增通过。

## 验证入口

- `verify_story_layers.py --actor-filter --rightward-motion --vertical-dip --stationary-brackets --games-selected 0`：独立原始 DAT 解码、源内静态图层重放和 Pillow 像素对照；不冒充完整脚本 VM。
- `verify_story.py --games 0 --until-boundary --movie-completion secondary`：手机实际按钮、原始音频哈希、页面文字与图片、演出事件、横屏显示、终止边界及 VM 释放。本批电影由测试器明确点击“返回剧情”跳过，不声明自然播完。
- `verify_motion_frames.py --include-stationary`：严格要求第 56、57、60、159 页动作捕获齐全；前两页仍验证真实中间位移，后两页要求所有采样像素一致且计时完整。每帧均使用独立 DAT 原图和 Pillow 重建。
- `verify_motion_cancel.py --page 60`：从标题推进，在第 60 页动作期间触发后台，检查无迟到帧、下一页或错误，以及音频缓存与 VM 清理。后台退出仍结束会话，不声明支持后台恢复或完整存档。

所有原始游戏文件、帧捕获、截图、音视频和 APK 仅保留本地；仓库只记录实现、验证脚本与可核查的元数据报告。

## 真机主回归结果

`brackets-batch19-native.json` 记录 BLESS 原生 ARM64 真机 175 页回归。页面元数据、PNG 和原脚本文字全部通过；82 个音频请求通过原始 DAT 哈希及播放器事件检查，另由 `brackets-batch19-audio-evidence.json` 复核，没有仅依赖终止区间豁免的音频条目。两次无参 BGM 停止均在释放播放器后 ACK。电影实际播放 184 帧后由验证器点击跳过，再继续进入章节。

第 56、57、60、159 页各捕获 8 帧，共 32 帧通过独立原图/Pillow 逐字节对照，见 `brackets-batch19-frames.json`。右移和纵向往返仍有不同的中间画面；两处 `[]` 各自的全部采样像素一致，且都有中间采样及 250 ms 末帧。第 60 页宿主 begin→finished 记录为 285 ms，第 159 页为 283 ms，包含合成、上传与调度开销，不声明精确 250 ms 的屏幕呈现或恒定帧率。

175 页最终场景及 11 张转场目标图通过独立图层/Pillow 核对，见 `brackets-batch19-layers.json`、`brackets-batch19-effects.json`。第 60、159 页实际 UI 截图确认夜色和白天场景均横屏显示，对白可见；截图只保存在本地。到达准确的不支持组合边界后 VM live bytes=0，正常结束时音频资源也全部释放。
