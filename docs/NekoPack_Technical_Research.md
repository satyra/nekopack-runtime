# NekoPack 技术研究

## 结论

资源读取有足够公开线索进入 Phase 1；通用 Android 游戏执行环境仍需脚本与引擎行为逆向。本轮完成源码级调查和四部曲静态样本检查，**没有完成完整引擎逆向，也没有 APK**。最关键的缺口不是 DAT 解包，而是脚本语义、系统 UI、动画时序、补丁覆盖和存档恢复。[N1–N4、X1–X3、G1–G2、L1，见 Sources.md]

## 已有成果

NekoPackExtract 是 C# 解包/PNG 导出与 C++ MNG 回封工具集合。DAT 解密、按哈希索引读取、Ogg/PNG/MNG/PSD 魔数分类已有实现。README 提供 NekoPackRebuilder 用法，但本次源码清单没有对应 Rebuilder 源码工程；不能宣称其全部二进制内部行为已审计。[X1–X3]

Niflheim 增加名称哈希匹配、parity 检查、DAT 回封/生成、补丁顺序字段说明及脚本汉化提取。MNG 导出保留 tEXt，作者明确指出引擎会使用该块做索引。它有很好的格式研究价值，但不是运行器；专用 name.txt 和作者报告不能外推全部作品。[N1–N4]

GARbro 还提供另两种布局和加密方案，表明同一 NEKOPACK 魔数不足以区分版本。未发现本轮所审查工程提供完整 NekoPack VM；这不等于证明网上不存在其他实现。[G1–G2]

## 本机样本

四部曲 22 个 DAT、51,201 个资源条目均完成索引边界与块长度验证，推导资源末尾等于文件末尾。35 个 DAT/EXE 文件记录了完整 SHA-256。EXE 的 NEKOPACK 字节候选未形成通过本轮 /1 布局校验的内嵌封包；不能推断 EXE 不包含其他形式的数据。[L1]

BLACK and WHITE 的脚本位于独立 script.dat；其余三部 script 目录位于 system.dat。BIRTH for YOURS 的 patch101.dat 包含 32 个 script 条目且顺序字段为 301；基础包顺序为 0。实际覆盖及同优先级顺序须原版动态验证。[L1、N1]

图像包前缀均分类为 PNG，MNG 集中出现在 system.dat。音频前缀主要为 OggS；尚未读完 codec headers，不把容器魔数等同 Vorbis/循环点支持。四部曲属于同一系列、包含汉化安装副本，不能代表不同年代全部 NekoPack 引擎。[L1]

## Android 可行性与难点

以下为设计判断：不执行 x86 EXE；Rust 重现资源、脚本与运行行为，Kotlin 管理目录与应用生命周期。资源文件可通过 SAF 授权读取；URI 不能直接当作文件系统路径。[A1]

- 哈希目录/文件名：按字节编码建立键，保留未知哈希与冲突；不能靠单作品全量词表维持运行。[N2、G1]
- MNG：PNG 提取不保留完整播放、对象状态和时序；必须按样本确定支持子集。[N4、X3、M1]
- 脚本：已见文本语法，不应先设计假定的二进制 opcode；控制流和系统命令需行为证据。[N3、L1]
- 存档：必须保存执行与等待状态，不只行号；原版存档互通未知。（设计）
- 内存与 I/O：大包不能整体载入，预先索引 + 按资源读取；资源内部解密具有反馈状态，不能无状态从任意中点开始。[X2、G1]
