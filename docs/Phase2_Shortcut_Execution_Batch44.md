# Batch 44：剧情快捷键实际执行

## 原版依据与本批范围

BLESS 原始 `system/shortcut.nut` 的 Trap 将功能键事件减去 ID_FUNC，按索引读取当时的 Config.ShortCuts，再通过 SHORTCUTS / InvokeCommand 分派。`config.nut` 默认 F1=CONFIG、F2=MENU，F3～F12 可编辑；空绑定不触发命令。`system.nut` 为 AUTO、SKIP 调用各自切换函数，为 CONFIG、QUIT 调用对应系统入口。

本批将当前绑定接入真实键盘事件：CONFIG 打开已有原版设置页，AUTO / SKIP 调用共用 Rust 会话状态，QUIT 请求宿主结束当前运行并销毁 VM。MENU、存读档、日志、隐藏等尚未接通的动作明确返回 unsupported，空绑定返回 unbound；二者都不推进脚本。没有声称原版侧栏图标、全部快捷动作或原生 QuitGame 确认界面已经还原。

## 输入与生命周期

Rust 入口接收平台无关的 F1～F12 槽位及页面序号，每次读取当前 Squirrel Config.ShortCuts，不缓存 Android 版绑定表。原版设置改绑后立即生效，继续沿用原有配置持久化。核心检查槽位范围及动作名。

AUTO / SKIP 的开始只在当前未授予推进许可的对白中执行；忙碌状态返回 busy，不排队到另一页擅自开启。关闭已运行模式允许跨过当前页已授予的 ACK：不撤销该 ACK，但下一页不继续自动／快进。模式仍沿用 Batch 42/43 的互斥策略。

CONFIG 仅在对白安全点返回宿主请求，Android 在交付时再次检查页面及按钮可用状态；设置模态、后台、标题及关闭中的会话不分派剧情功能键。每次文字帧请求开始时同步撤销设置等按钮的可用状态，防止尚未交付的自动换页许可与打开设置竞争。自动与快进关闭均保留独立取消入口，不受帧请求门控，也不挂起／丢弃当前帧回调。

Android 消费 F 键 down/up，仅在非取消的 up 上分派一次，避免键盘 down 重复事件反复切换。请求串行经过现有 worker；宿主只处理窗口、设备键码和退出清理。DialoguePresentation 的 refresh 在没有在途请求时重新轮询，沿用请求代次使旧延迟任务失效。

菜单已呈现状态快照使用临时文件加原子重命名发布，避免设备验证读到覆写过程中的半份 JSON。

QUIT 当前对应验证宿主的“结束运行”：停止媒体并在原 worker 上关闭 VM，不保存剧情位置。本批没有声称原生 QuitGame 的确认对话框语义已经确认。物理键盘及蓝牙设备的按键转换尚未实测。

## 验证方法

新增核心测试覆盖实时改绑、AUTO→SKIP 切换、已授予 ACK 后取消快进、过期页面不能开始快进、空绑定、未实现动作不推进，以及 CONFIG 请求。原有原生预算／回调与场景测试继续运行。

设备验证器新增 `--shortcut-check`：通过原版设置实际把 F3 设为 AUTO、F4 设为 SKIP、F5 设为 SAVE、F6 设为 QUIT、F12 清空，再通过 ADB 的真实 Android keyevent 发送功能键。检查开关及取消、F1 打开设置、设置中 F6 不退出、SAVE／空绑定不推进、回到剧情后 F6 正常退出且 VM live bytes=0。重启确认新绑定保存，再从设置界面恢复原绑定及配置。

随后继续 Batch 43 快进与已读专项、57 页剧情元数据／场景 PNG 基线，以及 55 次自动换页、后台、设置、BGM 和角色动作回归。仅 BLESS、emulator-5568 的 x86_64 / libnb.so ARM64 翻译执行；没有访问 CG／回想详细内容，不提交游戏素材或截图。

## 最终实测结果

最终 APK SHA-256：`33f703c866152bfb8a6e476f719d99223c48a5500e92bf5077354b8adbd617aa`。

实际 F 键输入通过即时改绑、自动与快进切换、快进取消、F1 原版设置、设置内屏蔽退出、空绑定及未实现 SAVE 不推进、F6 正常退出与 VM live bytes=0 检查。重启确认改绑保存；结束后另外只读核对全部十项绑定，直接解码设备 SharedPreferences 中的 NKCF v6，确认与本轮开始时的十项绑定一致。

最终 APK 同时通过 57 页既有剧情基线、快进／跨会话已读专项及 55 次自动换页（19 页真实语音完成回调、36 页无语音等待），包含设置、后台、BGM 和角色动作。147 个顶层 Rust 测试、7 次隔离宿主原生探针、17 个 Python 测试、验证器语法检查、fmt、Clippy 及 NDK ARM64 构建通过。

首轮通过后增加文字请求在途时的按钮门控，第二轮捕获自动关闭按钮被门控而未响应的回归并超时。随后将关闭自动改为全局取消，不撤销已授予的 ACK；新增核心测试后继续回归，又捕获设置诊断 JSON 覆写时的半份读取；改为原子发布快照并确认中断时原配置未变后，对最终 APK 完整复跑。最终 UI dump 重试 1 次，ADB 读取超时重试 0 次。

详情见 `research/shortcut-execution-batch44-emulator.json` 与 `research/shortcut-execution-batch44-checks.json`。结果仅代表本次 BLESS 样本和模拟器 ARM64 翻译执行，不代表所有动作接通或全篇通关。
