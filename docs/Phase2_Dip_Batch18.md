# Batch 18：BLESS `_` 纵向往返与后续对白

本批继续使用共用 Rust Runtime，仅对 BLESS 在 PGKM10 原生 ARM64 真机验证。目标是执行 `012402:81` 的 `.img6 _`，保留此前右移后的 X 坐标和夜色滤镜，完成往返后继续对白。不增加其他平台宿主，不修改原始游戏脚本。

## 原版依据

`research/verify_original_dip.py` 对本机 BLESS 原 EXE 校验指令、常量及代码片段 SHA-256，并确认 EXE 哈希与 Batch 17 原版证据相同。报告为 `dip-batch18-original.json`。并行对白调度沿用 Batch 17 对原 `message.nut` 和 `Screen.Render` 绑定路径的证据。

- `0x43cfb3..0x43cfb9` 将 `_`（0x5f）派发到 `0x43d007`，累加正数到纵向瞬态分量；缺省计数是 1。
- `0x43d060..0x43d06e` 将该值乘以 50，写入动作结构 `+0x10`，与永久 Y 位移的 `+0x08` 字段不同。
- 默认 duration 为 250 ms。`0x438794..0x4387d6` 使用 `sin(pi * elapsed / duration)` 乘以瞬态分量，加到当前基准 Y，再按向零截断转换为整数。
- `0x437a1c..0x437a22` 在角色绘制时把当前 Y 加上画布中心；因此单个 `_` 是屏幕 Y 正向的偏移：先向下，125 ms 时达到 50 逻辑像素，再回位。不能仅凭剧情用语推断为向上的永久位移。
- 队列完成时只把永久 dx/dy 加入基准位置；瞬态分量不提交。空队列把显示位置恢复为基准位置。因此结束后 X/Y 均不因 `_` 改变。

以上是原版机器码与既有系统脚本依据，不是动态原版截图或全版本兼容证明。

## 实现与边界

`motion.rs` 将位置扩展为二维，保留既有右移曲线，加入单个 `_` 的半周期正弦纵向动作。所有插值仍在以画布中心为原点的坐标系中向零截断，避免负坐标出现一像素误差。构造时检查瞬态峰值的整数范围。

`scene::plan` 仅允许末尾单个 `_`；纯动作保留图层顺序、资源缓存和已有滤镜。解析符号前继续检查嵌套 imagemap 宏，避免将未展开的宏名误当作动作。`__`、`_2`、混合动作、同一角色的多项待执行队列，以及动作与显式转场的组合仍明确报错。

继续复用 Page motion 元数据、`page_frame` 和 JNI operation 8。页面静态 PNG 表示最终稳定场景，动画帧不会修改缓存页面、推进 PC 或占用一个额外的脚本 ACK。正常结束和提前翻页都恢复基准 Y；旧页帧请求不能干扰下一页动作。Android 渲染通道无需新增动作算法，只给验证入口增加指定对白页的切后台触发条件。

## 验证入口与可信度

- `verify_dip_batch18.py`：真实原始 DAT、56 页前缀字节相等、59 页数量、动作元数据、回位后页面和准确下一边界。
- `verify_story_layers.py --actor-filter --rightward-motion --vertical-dip --games-selected 0`：独立 DAT 解码、源内图层重放和 Pillow，对照所有最终场景像素。静态重放只用于这些有界片段，不冒充完整脚本 VM。
- `verify_story.py --games 0 --movie-completion secondary --motion-captures ...`：实际手机按钮、页面/原脚本文字、原始音频哈希、播放事件、横屏截图、右移及纵向往返帧、终止边界和 VM 清理。本批明确点击跳过开场电影，不重复声称验证自然播完。
- `verify_motion_frames.py --include-dip`：核对两个动作各自的帧序列，使用独立原图、Pillow 和原版曲线重建每一帧；纵向动作必须有不同的中间画面，首末帧必须完全一致。
- `verify_motion_cancel.py --page 57`：从标题推进，在第 57 页动作显示期间触发后台退出。验证目标页确实显示初始帧，取消后没有完成事件、迟到帧、下一页或错误，音频缓存及 VM 释放；此前第 56 页右移不会触发退出。

核心测试还覆盖纵向峰值、负坐标截断、整数溢出、纯移动滤镜保留、提前翻页、右移尚未结束便切换到纵向动作以及过期页序号。它们补充真机回归，不能替代真实画面与生命周期测试。

## 真机主回归结果

`dip-batch18-native.json` 记录原生 ARM64 真机 59 页回归，24 个音频请求均通过原始 DAT 哈希与播放器事件核对。电影在播放 188 帧后由验证器实际点击“返回剧情”跳过，随后正常进入章节。终止边界为上述 `[]`，VM 受管内存为零；本批没有运行模拟器或其他三部。

第 56 页右移采集 8 帧，第 57 页纵向往返采集 9 帧，共 17 帧全部通过独立原图/Pillow/曲线逐字节对照，见 `dip-batch18-frames.json`。纵向采样时刻为 0、17、56、94、134、171、210、249、250 ms，首末 RGBA 完全一致，中间帧确实改变；X 坐标一直为 990。24 项音频事件另由 `dip-batch18-audio-evidence.json` 复核。

动画的逻辑时长为 250 ms；第 57 页最后一帧上传显示记录在开始后的 311 ms，仍存在逐帧合成、JNI 传输及宿主调度延迟，不宣称精确 250 ms 屏幕呈现或恒定 60 FPS。静态原版证据和独立像素对照不能替代动态原版屏幕验收。

59 页最终场景和 4 张转场目标图也通过独立图层/Pillow 核对，见 `dip-batch18-layers.json`、`dip-batch18-effects.json`。第 57、59 页的真实 UI 截图确认对白和横屏显示，截图仅保存在本地。
