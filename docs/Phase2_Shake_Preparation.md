# Shake 接入前：原版语义与 Rust 模型

本轮交付是 `shake` 的原版数学核对、平台无关参数/位移模型和既有路径回归，**不是 Android shake 功能完成**。`StorySession` 仍在该指令明确停止；没有跳过指令推进剧情。Android 宿主、FFI 和旧验证报告未修改。

## 已核对的原版事实

只读分析本机原始四部曲 EXE，文件 SHA-256 与上一批记录一致。`research/verify_original_shake.py` 核对常量、调用顺序、正弦指令及整数舍入方式，输出 `research/original-shake-math-verification.json`。仅保存地址、哈希和事实，不提交原始二进制或游戏资源。

- BLESS/BIRTH 位移计算位于 `0x441d54..0x441dae`，BRAVE 位于 `0x4957f4..0x49584e`，BLACK 位于 `0x441caa..0x441d04`。
- 横向使用 `sin(t / 7) * ax`，纵向使用 `sin(t / 8) * ay`；t 为经过的毫秒。原版通过 x87 `fsin` 计算，转换辅助函数把舍入控制改为向零截断，再执行 `fistp`。
- 原版横向常量的 80 位尾数存在编译产物差异；不能把四部作品的机器码视为完全相同。当前 Rust 使用 f64/libm，未宣称与 x87 每一个时刻逐位一致。
- 本机 BLESS/BIRTH 原始 EXE 的 SHA-256 相同，因此这两项静态核对不算两个独立版本；两款游戏的 DAT 剧情回归仍分别执行。
- BRAVE 参数解析函数 `0x491558`：默认 ax=8、ay=8、span=250；选项按顺序应用。`short/long` 对 span 整数减半/加倍，`honly/vonly` 把另一轴置零，`big/small` 对两轴加倍/整数减半；`once` 在所有选项处理后把 span 置为 50。关键赋值和分支位于 `0x491571..0x49158f`、`0x491e2d..0x49206c`。其他三款参数解析器尚未逐条复核，不能将 BRAVE 的参数审查描述成四款全覆盖。
- BRAVE 执行循环 `0x4957ec` 比较经过时间与 span，到达或超过 span 时退出；其间处理消息及绘制，脚本执行需等待该命令返回。数学模型到期返回 `None`，不擅自把它解释为最后绘制一帧零偏移。

复验工具只验证原版文件的静态事实，不调用原版游戏执行 shake，不证明 Android 画面正确。

## Rust 修改

新增 `crates/nekopack-runtime/src/shake.rs`，提供有序选项解析、时长和逻辑像素位移。未知参数、时长/振幅溢出显式返回错误；这属于输入边界约束，不模拟原版整数溢出。时间先与时长比较，再转换为浮点，因此超大宿主时间不会误算相位。

新增三项测试覆盖：已核对相位采样、负位移向零截断、到期/超大时间、参数顺序、once 最终覆盖、单轴、零时长、未知参数和溢出。它们是数学与参数单元测试，不是完整演出测试。

## 尚未闭合的画面语义

BRAVE 在 `0x495764` 调用 `0x4846e4` 生成快照，随后调用 `0x59a62c -> 0x59a8b8` 裁剪拷贝到画面缓冲区；这不是将一个 Android ImageView 平移的充分依据。需要进一步核对：

1. 快照包含哪些图层，是否包含文本窗；草稿场景与当前显示场景如何选择。
2. 位移暴露的边缘是否保留上一帧，以及消息/重绘路径是否重新初始化目标缓冲区。
3. 命令结束和用户中断后，下一次正常绘制怎样恢复画面。

因此本轮没有接入 `StorySession` 或 Android，也没有增加未经验证的黑边填充、自动归零、随机抖动实现。电影仍不在本轮范围。

## 回归口径

新增模型在桌面运行时测试及 Android ARM64 静态编译检查中验证。桌面原始 DAT 回归使用本轮新编译 CLI；Android 回归使用上一批已安装 APK，仅检查原有基线，**未执行新增 Rust 模型**。

`cargo test -p nekopack-runtime` 16 项通过；桌面及 `aarch64-linux-android` 的该 crate Clippy（`-D warnings`）通过。ARM64 检查仅证明代码能面向该目标静态检查，不是新增模型的真机执行证据。

- `research/shake-preparation-desktop-baseline.json`：四部曲仍分别为 12/8/72/16 页，原有 movie/shake 停止点、PC、调用深度及预算计数保持不变。
- `research/shake-preparation-arm64-baseline.json`：真实 ARM64 手机的既有原始 DAT 路径。
- `research/shake-preparation-translated-baseline.json`：x86_64 模拟器经 libnb 翻译执行 ARM64，不能当作 ARM64 真机结果。

两台设备各通过 108 页及 49 个音频请求的既有校验，安装包哈希与上一批一致。模拟器自动化出现 6 次 UIAutomator 空根节点提示，随后流程完成；报告保留提示计数。通过依据是逐页状态/图片、效果和音频断言，不仅是进程退出码。

本轮没有重新执行分配失败注入或后台切换专项，也不引用旧报告作为本轮新增模型的动态验证。设备回归包含已有的结束会话与 VM 释放检查。

## 下一步验收门槛

先闭合上述快照/边缘/恢复语义，再把模型接入 Rust 效果请求与 Android 帧调度。必须补充重复轮询不推进 PC、错误 token、取消/销毁不晚回调测试，以及独立像素/偏移对照。之后才扩展四部曲剧情范围，在真机与翻译执行模拟器分别重跑并发布新 APK 验证结果。Android 优先，横屏和统一 Rust 执行链路不变。
