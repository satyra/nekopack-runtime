# Batch 48：剧情菜单存档／读档

## 原版证据与范围

BLESS 原版窗口实测：剧情菜单 Save 打开每页十槽、共十页的普通存档页；写入可见空槽 001 后留在存档页；返回后仍是原对白；推进一句，再从 Load 选择 001，可以回到保存的对白和角色画面。本次未观察到确认弹窗。原版测试实际创建了此前为空的槽 001，未覆盖已有可见存档。观察记录和提取脚本摘要见 `research/original-save-batch48-observation.json`。

原版 `SaveData` 先保存 SaveInfo，再调用原生 SaveState。LoadData 恢复章节标签、更新窗口标题，原生 LoadState 成功后 `Sleep(1000); throw null`。这证明恢复不能只是改列表标签；它不证明原版的完整二进制存档格式、内部 VM 所有权或音频采样位置。

本批接通剧情菜单 SAVE／LOAD，Android 使用十页共 100 槽的简洁选择页，支持分页、存读模式切换、覆盖本运行器槽位、空槽禁用和返回原对白。尚未复刻原版存档页皮肤、缩略图与标题读档入口；快捷存读、消息日志也不在本批范围。

## 核心快照

Rust 核心输出独立版本格式 `NKSV\x01`，不读取或覆盖原版 `.sav`。整数固定小端、字符串 UTF-8，数据不含平台指针、文件描述符、JNI 对象或 Squirrel 堆。Android 仅负责槽位文件、同目录临时写入、文件同步和原子 rename，以及模态 UI、设备音频。

保存内容包括脚本调用栈、每帧 PC 与嵌套 map 边界、常量／变量别名／变量槽、已消耗及最大指令预算、调用深度上限、章节标签、当前对白和语音标识、场景图层顺序／滤镜／像素／坐标、每角色动作队列及进度、持续 BGM／ENV／循环 SE 标识。

恢复直接建立保存的 Machine 状态，不从开始重新执行剧情。脚本源从原始 DAT 读取，并核对保存时的源摘要；角色像素以 PNG 保留，避免重新应用已生效的夜间滤镜。配置与累计已读记录仍属于用户配置域，不随旧存档回退。恢复后的对白 token 与音频 token 使用当前会话的新编号，旧回调不能推进新页面。

Squirrel 仍使用当前已加载系统模块的 VM；本批恢复运行器当前实际使用的章节状态和 Rust Variables，没有宣称可以序列化任意 Squirrel 协程或任意脚本对象。今后新增会影响剧情的可变系统状态时，必须纳入存档契约并调整格式版本。

存档最多 16 MiB；读取长度、集合计数、UTF-8、变量引用、脚本位置、动作时钟、场景解码预算均有边界。FNV-1a 摘要用于损坏检测，不是安全签名。DAT 身份是挂载索引布局摘要，加上当前调用栈脚本的内容摘要；不是整个游戏全部资源的加密内容指纹，不保证兼容同布局资源替换或其它引擎版本。

## 恢复与失败边界

读档分为准备和提交。准备阶段校验文件并建立独立 Machine／Scene／动作与音频数据，失败时保留当前对白和播放器。成功后宿主停止旧对白回调、旧角色调度及音频，提交已准备快照，再展示保存的页面。保持一个 Squirrel VM，不同时运行两个剧情 VM。

持续音频恢复资源、声道和循环状态；当前对白语音重新开始，自动和快进关闭。没有实现采样位置恢复，也不把一次性 SE 的中间播放位置当作已支持能力。当前文字从该页重新显示；原版部分文字的精确恢复时序未验证。

设备首轮发现 JNI 将损坏存档的普通校验错误送入通用致命清理路径，导致后续取消操作没有当前 VM。已将存档导出／准备阶段的普通错误明确作为可恢复错误返回；提交错误和 panic 仍保留原有销毁路径。失败轮保留本机日志，不计入通过结果。

## 验证

新增 Rust 测试覆盖嵌套调用／map 与变量恢复、保留执行预算、截断与尾随数据拒绝、滤镜与图层像素保持、动作队列时钟，以及损坏存档不改变当前页面并能取消后继续。设备回归直接使用 SAF 原始 DAT，历史页面文件仅作为比较基线。

设备为 emulator-5568，x86_64 + libnb.so ARM64 翻译执行，不能代替 ARM64 真机结论。角色动作页设备验证与中间动作时钟单元测试分开统计：自动菜单探针打开时动作可能仍在进行，但 UI 操作延迟可能使选槽保存时动作已经结束。

最终 APK SHA-256：`c7594cfb9bedb81270aae7d538b026fe0f6787cde784de1af223744d905c3789`。

154 个顶层 Rust 测试、7 次隔离原生探针、17 个 Python 测试通过；fmt、Clippy all-targets / deny warnings、验证脚本语法检查和 NDK r27d / API 23 ARM64 构建通过。

存读档专项通过：空槽禁用、覆盖写入一致性、分页与模式切换、后台保持存档模态、首段存读／继续、强制重启进程后读档、57 页基线比较、角色动作页恢复后继续、BGM 与语音重启、损坏槽位拒绝后取消并继续原剧情。独立检查确认恢复音频与原音频资源 SHA-256 一致、旧音频 token 不再回调、正文 token 单调递增，各会话关闭后 VM 分配为 0 且音频缓存清空。

兼容回归通过：三次返回标题并重新开始、原版菜单 SAVE／LOAD 取消不推进对白、设置页返回与后台切换、BGM 同一播放器暂停恢复、另一次 57 页普通剧情比较。本次未重跑完整自动／快进专项，不将空结果对象计为通过。另行检查了横屏槽位页，滚动至槽 010 存档、取消后原对白保持，并正常关闭 VM。

详见 `research/story-save-batch48-emulator.json`、`research/story-save-batch48-independent.json`、`research/story-save-batch48-settings-emulator.json` 与 `research/story-save-batch48-checks.json`。本轮全部设备结果均为 ARM64 翻译执行。
