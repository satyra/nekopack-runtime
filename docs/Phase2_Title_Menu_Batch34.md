# Batch 34：BLESS 原版标题显示、触摸与剧情入口

本批将原始 DAT 标题资源接入 Android。正常启动应用时，已有 SAF 授权则进入 BLESS 标题；没有授权则先选择 DAT 目录。原有 `story_game` 自动剧情回归入口保留，新增 `title_game` 用于标题交互验证。

## 执行链路

共用 Rust bootstrap 执行启动定义与系统模块，停在尚未完成的 `.map title` 请求。等待输入期间不执行菜单处理函数、不完成请求，也不推进 PC。`TitleSession` 持有同一份 DAT、Machine、Variables 和 SystemVm；确认开始后设置实际输入 ID，调用原来的 `com["map"]`，由脚本 `.case 1` / `.load story1` 进入现有剧情边界，再将这些对象移交 `StorySession`。

没有重建 VM，没有另写 Android 剧情解释器，也没有通过 Squirrel 根 VM 挂起实现等待。新增单元测试检查等待时的步数、变量与 pending request，以及恢复后菜单只调用一次、VM 全局状态和变量均被保留。

## 标题显示与输入

依据原版 `select.nut::ViewNormalMap` 的初始化顺序，`host/title.nut` 构造展示计划：`BASE`、按条件叠加的基础图层，以及按 `.map` 行号绑定的按钮。启用和选中状态仍调用原游戏 `FlagCheck`；不在 Kotlin 中重写变量判断。展示适配器不调用菜单目的地。

Rust 从 `system/title.mng` 解码原始 PNG，采用原始 DEFI 坐标进行合成。正常、高亮和选中图层遵循已有 sprite 命名；热区来自 `* 按钮名`，缺少独立热区时取普通图层矩形。BLESS 开始按钮的原始热区是纯色矩形。当前实现是已观察到的 normal-map 标题配置，不宣称完整 MNG 动画或任意形状像素掩码支持。

Android 只按实际视口等比绘制，并将触点反变换为游戏坐标。Rust 判断按钮是否启用，处理按下、移动、抬起和取消。拖出后再拖回仍取消本次点击；抬起必须匹配先前按下；后台或失去窗口焦点会取消按压。标题使用整个可用内容区域，隐藏剧情调试控制条，保持横屏与原始宽高比。

JNI 操作 17 打开标题，18 传递 `[kind,x,y]` 输入，3 统一关闭标题或剧情。所有 VM 操作仍在同一专用 worker 上；错误路径同时清理标题状态。输入序号和 UI 提交记录使设备验证能够等待真正处理完成，避免快速自动输入早于上一帧恢复触摸而导致测试歧义。

## 本批边界

- “开始游戏”进入实际脚本分支；“结束”执行宿主关闭并释放 VM。
- 读档、原版设置等其他入口尚未接入，触摸时明确提示并留在标题，不擅自执行其脚本。
- 未打开或分析 CG、回想的详细图像、场景或对白；没有调用这些目的地。原有启动流程仍加载游戏系统模块声明。
- 初始标题状态沿用当前会话变量。持久化通关解锁、读档、返回标题、原版设置页和完整 UI 音效不属于本批完成范围。
- 素材、截图、字体和完整原脚本仅保留在忽略的本地工作目录，不提交至仓库。

## 验证与证据

`platforms/android/verify_title.py` 使用本地原始 `title.mng`、标题脚本和菜单初始化规则独立验证，没有用运行时展示计划充当像素基准。

- 独立 Python PNG 合成与 Rust 正常标题逐像素相等；按下开始按钮时，高亮画面同样与原始图层独立合成相等。
- PGKM10 / Android 15，`aarch64`，native bridge 为 `0`，属于 **原生 ARM64**，不是模拟器翻译执行。
- 实际屏幕截图经过独立浮点视口与双线性采样对照：平均绝对通道误差约 0.191，P99 约 0.531，最大约 1.116（8 位通道单位）。这是 Android 显示与原始素材合成的对照，不是原版 Windows 动态截图完全一致的证明。
- 空白触摸不启动；按下高亮；拖出再拖回不启动；按压时 Home 取消；返回前台后菜单请求和步数不变；未接入的读档入口留在标题。
- 实际点击开始后前五页的完整页面元数据、场景 PNG 与既有基线一致。分别从标题和第五页关闭，VM 追踪存活字节均归零。
- `research/title-batch34-phone.json` 保存 APK 哈希、设备执行模式、上述结果和场景摘要。
- `research/title-batch34-checks.json` 保存 Rust、Clippy、Python 与 NDK 构建检查摘要。Rust 新增同 VM 菜单等待/恢复、触摸取消与边界测试。

标题等待和点击验证是本批新增验收。普通 Launcher 启动也已确认进入标题。既有对白控制回归通过 KeepVoice 0/1 各五页；生命周期回归通过连续 61 页、5 次后台切换、视频跳过后继续、BGM 和角色动作恢复及关闭释放。结果保存在同批 `dialogue` 与 `lifecycle` 报告中；这些既有回归使用直接剧情入口，不能冒充从标题出发的更长流程验证，也不代表视频自然播放结束。

## 下一步
